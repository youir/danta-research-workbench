# 思路检查、主张与人的决定

## 三个检查节点（保留原“三次冻结”的目的）

1. 问题边界：想解释什么现象，范围是什么，回答到何种程度有价值。
2. 文献定位与解释：最接近研究支持到哪一步，尚有哪些候选解释，什么结果会改变判断。
3. 研究架构：拟提出什么主张，用哪些证据检验，实际资源与限制是什么。

节点用于避免 AI 偷换问题，不要求每次讨论都停下来签字。未定内容可作为显式假设继续检索、比较或草拟方案，不代表用户已选定方向。只有要把暂定想法记为“用户选择的研究基线”时，才需要内容明确的决定。已有决定沿用；新证据改变关键前提时，说明影响并重新讨论。

根据上下文解释简短回答：在清楚列出一个具体选择后回答“好，就按这个方向试”可以记录为试行选择；面对多个分支只说“继续”，只能视为继续讨论，不能认定选了某个分支。确有歧义只追问歧义本身，不要求逐项重复确认或特定口令。尽量准确引用；概述必须标明概述。

## 科学证据、人的选择与阻塞分开

- **内容类型**：文献证据 / 用户自述 / 直接数据或观察 / 系统推断 / 待检验假说 / 待核实。
- **证据阅读范围**：元数据 / 摘要 / 部分全文 / 全文 / 附件；核验一篇论文不等于其结论已经普遍成立。
- **方案决定状态**：PROVISIONAL（暂定）/ CONFIRMED（用户已选择的工作基线，随时可修订）。CONFIRMED 不表示假说成立、伦理获批或导师已批准。
- **可推进性**：可推进 / 部分受限 / BLOCKED（某个具体动作受阻）。写明阻塞动作、原因、解除条件和仍可做的事，不把整项研究一概锁住。

兼容旧三态记录，但新记录分开“用户决定”和“能否继续”。旧 CONFIRMED 不能升级为科学证明；旧 BLOCKED 应指出到底阻塞哪一步。

## 主张—证据映射（Claim–Evidence）

不从“观察缺口”直接跳到“根本成因”。在未验证时写“候选解释或研究目标”；描述型/预测型研究不强行填机制。

每行：问题或观察及来源 → 候选解释/目标 → 有边界的拟检验主张 → 已有证据及来源ID → 尚缺证据 → 计划的比较/对照/分析 → 不同可能结果对主张的影响 → 资源与限制。

区分已有证据与计划获取的证据。通常通过相互补充的证据支持主张，不承诺某一个“决定性实验”能证明整个机制。实验、预测和结果解释要与拟提出的主张相匹配。

证据不足时可补证据、收窄主张、调整设计、保留分支或暂缓，由研究者结合条件选择。不要强制二选一，更不要把可行的证据路径写成已得到的结果。

## 何时写方案

用户已选择要继续思考的问题，或者明确要求比较不同分支时，即可草拟相应方案，标明暂定与缺口。开题前应清楚交代主张边界、证据计划和关键资源；不要求先完成研究结果、所有配图或全部验证实验。
