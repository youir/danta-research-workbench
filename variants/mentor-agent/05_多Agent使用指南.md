# 多 agent 怎样协助蛋挞

主引导是唯一入口，负责理解你的想法、恢复上下文、选择负责角色并汇总结果。文献证据、方法统计、生信数据库、论文写作、组会科研表达、知识库整理和质疑审查各有对应 agent；你只要说目标，不必记 agent 名称。简单任务仍由主引导直接处理。

## 开始方式

在工作台中对 AI 说：

> 请按本包 multi-agent.md 协作协议工作。根据我这轮的目标选对应职责 agent；有相互独立的子任务时才并行，并由主引导核对和汇总。先了解我的资料与环境，不要急着给题目。不能运行子 agent 时，请明确用单 agent 分角色分析。最终选择由我和导师作出。

## 配置与实际能力

项目的 `.codex/agents/` 提供七个 TOML 职责角色，`.codex/config.toml` 限制最多三个并发子 agent；它们继承使用者的模型设置，不配置密钥或新增 API 付费服务。打开项目后，是否加载仍取决于客户端版本与受信任项目设置。本包不修改全局配置。

参考：[OpenAI 官方 Subagents 文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)。配置依据该文档于 2026-09-24 核对；角色定义是本系统的设计，不是官方科研代理。

首次验证可让一个子 agent 只读本包入门指南，返回三个要点及文件路径；主引导记录是否真实派工与收到结果。这只验证调用链，不证明科研质量。若无工具或角色未加载，可以在通用子 agent 的任务消息中提供角色边界；仍不可用则降级为单 agent，不能假装并行。

## 保持思维优先

- 主引导先听你的困惑，选题决定不交给 agent。
- 每类复杂任务有明确负责 agent；文献核查和独立设计分析可并行，有依赖的工作顺序完成。
- 写作、生信和汇报 agent 只写本轮指定产物；主引导审阅后更新共享记录。
- 分歧作为值得继续思考的问题，不以多数票决定真伪。
- 多 agent 会增加时间与用量；只有独立任务值得拆分时才启用，不要求每轮全员参加。

技能安装与角色加载是两件事。Skills 的安装方式仍见原安装指南；仅安装主技能到全局目录不会自动复制项目角色配置，需保留本包的工作区结构。
