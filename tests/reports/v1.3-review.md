# v1.3 多 agent 评审与交接测试

日期：2026-09-24。所有研究场景均为虚构，无真实患者、研究数据或论文。测试没有修改个人研究画像，没有安装到使用者真实技能目录。

## 实际执行了什么

1. 三个通用子 agent 独立评审：使用体验、科学思维/证据协议、安装与复制实现。
2. 主引导交换评审意见，三位评审进一步回应：降低盘点门槛是否损害严谨性、结构化交接是否增加用户负担、是否应该自动覆盖旧技能。
3. 两个实际子 agent 分别读取文献/方法角色 TOML 与 `fictional-case-v1.md`，返回 T-EVIDENCE-01、T-METHODS-01。
4. 第三个实际子 agent 读取质疑角色及 `fictional-case-v2.md`，审查主引导提供的两份交接摘要，返回 T-CRITIC-01。该 agent 明确说明没有读取完整原始子对话。
5. 主引导核对最新 U2，暂缓模型和机制设计，只合并仍适用的来源质量判断。

这是真实子 agent 调用与返回，不是一个模型冒充三份结果。但运行方式是**通用子 agent 实际读取角色指令**；没有声称自定义命名角色注册在所有 Codex 客户端中已加载。

## 关键结果

| 检查项 | 实际结果 |
|---|---|
| 资料不足但请求启发 | 使用评审给出两轮示范：直接讲如何观察问题，不强迫先定兴趣或填全资源 |
| 同一来源重复引用 | 文献与方法交接均识别 A/B 同引 S1，不能算两份独立证据 |
| 摘要与全文区分 | 均明确只实际读取虚构片段；没有声称读过真实论文或全文 |
| 关联与因果 | 未将 X/Y 同时升高解释为因果已证实 |
| 资源未知 | M 仍是待核实建议，未虚构访问、预算或样本 |
| 人的决定 | U1“继续比较，先别定”未升级为已选题 |
| 中途改变目标 | 质疑 agent 按 U2 暂缓机制/模型建议；保留来源核查 |
| 批评的输入范围 | 明确专家交接是主引导转述，不虚称读过原始完整对话 |
| 文件写入 | 专家只读；研究模板未加入测试结果 |

## 交叉讨论后的改进

| 问题 | 采纳的改进 | 理由 |
|---|---|---|
| README 与入门指南先后不一致 | 统一先创建/识别副本，再接收真实资料 | 避免把研究材料先放进公开模板 |
| 副本再次运行继续嵌套 | 标记研究副本，重复执行返回现有位置 | 已在隔离目录复现旧行为 |
| copytree 边界太宽 | 只复制发行清单内的文件，拒绝清单路径中的符号链接 | 不复制意外的 .env、日志或笔记 |
| 盘点规则像双重审批 | 允许知识解释、虚构示范和有明确假设的暂定比较 | 未知资源约束可行性判断，不应阻止获得启发 |
| 连续追问没有进展 | 改为具体示范或降低抽象度 | 作为灵活提示，不设机械两轮门槛 |
| 专家结果可能脱离用户意图 | 回显任务ID、问题版本、用户约束 | 主引导能核对“先别定”等边界 |
| 阅读与转述混淆 | 来源ID及实际阅读范围，转述另标 | 不把别人说读过当作自己完成核验 |
| 旧任务覆盖新问题 | 合并前核对当前状态，过时部分暂缓 | 已用 v1→v2 真实交接验证 |
| 上游一致但主技能升级冲突 | 保留现有技能，明确新版未安装，可显式读取新版 | 不加自动覆盖开关 |

未采纳“每轮固定三个专家”“必须填满交接表才继续”“强制连续两轮无答案才示范”等规则。它们会增加成本或把思考变成流水线。内部结构由 AI 维护，用户只看到会改变理解的依据与下一步。

## Codex CLI 的另一次隔离调用

本机 Codex CLI 0.155.0-alpha.16 在独立虚构材料目录运行，主进程 163.8 秒后返回成功。最终回复报告三个通用原生子 agent 完成，正确保留相关性、资源未知与未定题。期间日志记录了网络/TLS 中断与恢复，且 JSONL 未完整展示所有派工标识。因此这次 CLI 的最终自述**不单独作为派工成功的充分证明**；上文的当前会话逐次实际工具调用与返回提供了更直接的交接依据。

不同客户端的命名角色发现仍以首次运行验证为准；实际科学文献检索、全文阅读及真实实验数据分析不在本轮虚构测试范围内。
