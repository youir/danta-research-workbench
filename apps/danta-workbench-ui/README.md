# 龚博士科研工作台 · Windows 桌面版

工作台以 Windows 桌面程序分发。安装后从桌面或开始菜单打开独立窗口；网页界面、本机 Obsidian 桥接和 Codex 交接服务随程序启动。Codex 仍是实际的科研协作入口；工作台不会自动发送启动语，也不会自动执行 Git 更新。

## 给龚博士安装与日常使用

打开 [GitHub Releases](https://github.com/youir/danta-research-workbench/releases)，选择 tag 以 `workbench-v` 开头且版本号最高的桌面版，下载 `Danta-Research-Workbench-<版本号>-x64-Setup.exe`，运行安装程序。安装时可以选择位置；安装程序会建立桌面快捷方式和开始菜单入口。之后双击“龚博士科研工作台”即可打开，不需要克隆仓库、安装 Node.js 或打开终端。

桌面程序需要 Windows 10/11 x64。要使用“创建 Codex 新对话”等交接能力，本机还需安装并登录 Codex 桌面版，同时让 Codex CLI 可被本机识别。程序会从 Windows `PATH` 和 `%APPDATA%\npm` 查找 `codex.exe` / `codex.cmd` / `codex.bat`；若安装在其他位置，可设置用户环境变量 `CODEX_CLI_PATH` 指向该程序。安装或修改环境变量后，重新启动工作台。

桌面程序将本机服务绑定到 `127.0.0.1:48921`，只接受工作台自己的本机来源，不向局域网开放。若此端口被其他程序占用，先关闭占用程序再重新打开工作台。

顶部“检查更新”会查询 GitHub 桌面版发布记录。发现新版后，下载并运行安装包即可覆盖更新；本机草稿会保留。Obsidian 知识库路径和授权只在程序运行期间保存在内存中，退出或更新重启后需要重新选择知识库并确认权限。

完整的首次部署和数据说明见[桌面版安装与维护说明](桌面版安装与维护说明.md)。

## 页面结构

- **开始：** 写下一个研究问题，或进入选题、论文、PPT、组会准备 / 复盘、生物科研日报五个任务整理区。每项工作都有可编辑草稿、启动语和文件名清单。科研 PPT 按“整理汇报任务 → 选择模板与单位标识 → 检查启动语”的顺序准备；内容区可选汇报形式、目标、听众和时长，再插入可编辑的填空框架，补充主题、真实材料、希望讨论的问题及待确认信息。所有引导项都可跳过，框架提醒只依据实际提供的研究材料整理，不推测或补造结果。工作台不预填具体病种、实验发现或研究结论。提供四套病理科研汇报模板的封面预览和 PPTX 下载，所选模板名及文件路径会写入启动语。可选内置海军军医大学或复旦大学上海医学院 Logo，也可选择暂不添加或在 Codex 对话提供其他获授权的标识。未选时，启动语会先引导确认实际汇报单位。首页的连接状态入口直接打开知识库说明，不代表已有研究记录。
- **研究记录：** 在知识库页明确授权“研究记录”后，读取 `05_课题项目_Projects/` 和 `10_日志复盘_Journal/` 中的 Markdown，显示标题、日期、摘要和相对路径；不会扫描其他目录。
- **机制图：** 单独入口，也能从 PPT 工作区进入。输入简短需求后生成绘图启动语；“查看制作过程”展开五步方法说明。BioTender 是可选技能索引，BioRender 是外部绘图平台，两个链接都不会携带研究内容。
- **文献与信息源：** 无需授权知识库即可输入公开 PMID，手动打开 NLM 的 PubMed Linked Discoveries 图谱；按该 PMID 发起查询，不附带本地文献资料。图谱用于探索相关文献与引文线索，不评价研究质量或复现成败。分别授权“文献证据”和“RSS 线索”后，可读取 `03_文献证据_Literature-Evidence/` 的 Markdown，以及 Obsidian RSS 插件现有缓存和 `01_收件箱_Inbox/02_RSS_动态线索/` 中的笔记。工作台只显示已有缓存，不刷新订阅或联网抓取全文。
- **归档：** 可按授权查看 `14_历史归档_Archive/`，或在明确启用“新建归档”范围后，填写标题和内容并新建 Markdown。只在 `14_历史归档_Archive/工作台归档/` 创建新文件，不覆盖或删除已有文件。
- **科研日报：** 选择 Codex 定时任务写入 `brief-YYYY-MM-DD.html` 的归档文件夹，查看逐日报内容、来源与覆盖范围；按需排版、预览并保存可分享的长图 PNG。浏览器记住所选文件夹句柄，再次打开时由用户授予本地读取权限；也可临时导入单份日报 HTML / JSON。
- **知识库：** 点击“选择 Obsidian 知识库”会打开系统文件夹选择器。选中后可按需检查标准目录，确认后只补齐缺少的空文件夹；旧目录名不匹配时只提示，不会自动搬动资料。随后逐项勾选读取/归档范围并确认授权；页面按需读取该页数据。连接路径和权限只存在于本机桥接进程内存，程序重启后需重新选择和授权。断开后清除连接状态。
- **检查更新：** 桌面版检查 GitHub 最新发布版本，并提供 Windows 安装包和更新说明；网页开发版仍比较仓库 `main` 并复制安全更新指令。

## 返回与恢复

知识库子页面提供返回按钮，按进入页面的顺序回到上一个工作区。首页和任务工作区的未完成草稿、已填写的引导内容及启动语会保存在当前浏览器的 `localStorage`；刷新或重新打开同一浏览器后，首页会显示“继续上次工作”，可恢复未完成任务或重新打开启动语。清除浏览器站点数据会清除这些草稿。知识库目录和授权不保存在浏览器中，需在本机服务运行期间重新连接。

## 当前数据边界

任务草稿、当前流程内容、PPT 模板/Logo 选择和未完成启动语保存在本机应用地址 `127.0.0.1:48921` 的浏览器存储中，退出重开可恢复，不上传到服务器。连接的 Obsidian 路径、勾选范围和读取授权只保存在本机桥接进程内存；页面只在进入对应模块时读取授权目录，并按模块只读规定子目录。归档写入另有单独授权，且只新建文件。工作台不会读取 Codex 历史对话。交接功能读取本机 Codex 项目列表，按选择在对应项目下创建新对话、设置标题、复制启动语并尝试打开该对话。当前 Codex 接口不支持把草稿直接预填到新对话输入框；打开后需按 `Ctrl+V` 粘贴，再由使用者检查并提交。工作台不会代为发送启动语。

## 维护者开发与打包

```bash
npm install
npm run check
npm run start        # 浏览器开发模式
npm run dist:win     # Windows x64 安装包
```

安装包通过 GitHub Actions 在 Windows runner 上构建。推送 `workbench-v*` 标签会创建包含安装程序和 SHA-256 校验值的 GitHub Release；用户从发布页下载，无需访问源码仓库。
