# 龚博士科研工作台 · Windows 桌面版

工作台以 Windows 桌面程序分发。安装后从桌面或开始菜单打开独立窗口；网页界面、本机 Obsidian 桥接和 Codex 交接服务随程序启动。Codex 仍是实际的科研协作入口；工作台不会自动发送启动语，也不会自动执行 Git 更新。

## 给龚博士安装与日常使用

打开 [GitHub Releases](https://github.com/youir/danta-research-workbench/releases)，选择 tag 以 `workbench-v` 开头且版本号最高的桌面版，下载 `Danta-Research-Workbench-<版本号>-x64-Setup.exe`，运行安装程序。安装时可以选择位置；安装程序会建立桌面快捷方式和开始菜单入口。之后双击“龚博士科研工作台”即可打开，不需要克隆仓库、安装 Node.js 或打开终端。

桌面程序需要 Windows 10/11 x64。要使用“创建 Codex 新对话”等交接能力，本机还需安装并登录 Codex 桌面版，同时让 Codex CLI 可被本机识别。程序会从 Windows `PATH` 和 `%APPDATA%\npm` 查找 `codex.exe` / `codex.cmd` / `codex.bat`；若安装在其他位置，可设置用户环境变量 `CODEX_CLI_PATH` 指向该程序。安装或修改环境变量后，重新启动工作台。

桌面程序将本机服务绑定到 `127.0.0.1:48921`，只接受工作台自己的本机来源，不向局域网开放。若此端口被其他程序占用，先关闭占用程序再重新打开工作台。

顶部“检查更新”会查询 GitHub 桌面版发布记录。发现新版后，下载并运行安装包即可覆盖更新；本机草稿会保留。桌面版把已确认的知识库路径、目录关联和具体授权范围保存在本机应用数据中。退出或更新重启后，一键核对并恢复原范围；目录变化或知识库被替换时暂停受影响的授权。

完整的首次部署和数据说明见[桌面版安装与维护说明](桌面版安装与维护说明.md)。

系统各层职责与科研任务路由见[完整体系架构](../../08_完整体系架构.md)和[科研工作流与能力路由](../../docs/architecture/科研工作流与能力路由.md)。本机任务卡的数据维护集中在 `src/features/research-tasks/hooks/useResearchTasks.js`；页面入口负责导航、表单交接和本机服务调用。

## 页面结构

- **今天：** 显示未完成启动语、最近一张任务卡和自由问题输入；首页草稿会直接回填。主导航按“研究任务、文献资料、汇报制图、设置”分区。选题与论文写作在研究任务区，研究记录、文献、日报和归档在文献资料区，PPT、组会与机制图在汇报制图区。每次从入口开始都会建立独立的本机研究任务卡，允许同一类型并存多项。卡片可记录任务名、本次目标、研究阶段、状态、下一步和待确认问题，并保留该任务的草稿、工作台记录的文件名和 Codex 对话编号；首页可恢复到对应工作区，也可重新打开该任务关联的 Codex 对话。研究阶段和状态由龚博士手动维护，工作台不读取 Codex 历史或自动判定任务完成。科研 PPT 按“整理汇报任务 → 选择模板与单位标识 → 检查启动语”的顺序准备；内容区可选汇报形式、目标、听众和时长，再插入可编辑的填空框架，补充主题、真实材料、希望讨论的问题及待确认信息。所有引导项都可跳过，框架提醒只依据实际提供的研究材料整理，不推测或补造结果。工作台不预填具体病种、实验发现或研究结论。提供四套病理科研汇报模板的封面预览和 PPTX 下载，所选模板名及文件路径会写入启动语。可选内置海军军医大学或复旦大学上海医学院 Logo，也可选择暂不添加或在 Codex 对话提供其他获授权的标识。未选时，启动语会先引导确认实际汇报单位。桌面端左侧显示知识库连接状态；窄窗口可从“设置 → 知识库与授权”查看。
- **研究记录：** 在知识库页明确授权“研究记录”后，读取两个标准目录及本人明确关联的现有文件夹中的 Markdown，显示标题、日期、摘要和相对路径；不会扫描未选目录。
- **机制图：** 从“汇报制图”进入，也能从 PPT 工作区进入。每次开启建立独立的机制图任务卡；从 PPT 进入时标记与 PPT 任务的关联，并带入前序内容、待解决问题、文件名与成果索引；两个任务各自保存，返回后恢复原任务。输入简短需求后生成绘图启动语；“查看制作过程”展开五步方法说明。BioTender 是可选技能索引，BioRender 是外部绘图平台，两个链接都不会携带研究内容。
- **文献与信息源：** 无需授权知识库即可输入公开 PMID，手动打开 NLM 的 PubMed Linked Discoveries 图谱；按该 PMID 发起查询，不附带本地文献资料。图谱用于探索相关文献与引文线索，不评价研究质量或复现成败。分别授权“文献证据”和“RSS 线索”后，可读取各自标准目录及本人明确关联的现有笔记文件夹；RSS 插件缓存仍只读本机已保存的数据，不刷新订阅或联网抓取全文。
- **归档：** 可按授权查看 `14_历史归档_Archive/`，或在明确启用“新建归档”范围后，填写标题和内容并新建 Markdown。只在 `14_历史归档_Archive/工作台归档/` 创建新文件，不覆盖或删除已有文件。
- **科研日报：** 可从日报页准备今日日报或 Codex 原生自动化的设置 / 暂停请求；工作台会创建 Codex 新对话并复制启动语，仍需在 Codex 中粘贴、提交并确认。自动化状态由 Codex 管理，工作台不读取开关状态。选择归档文件夹后可查看逐日报内容、来源与覆盖范围，并排版、预览和保存分享长图 PNG。浏览器记住所选文件夹句柄，再次打开时由用户授予本地读取权限；也可临时导入单份日报 HTML / JSON。Codex 工作区必须能访问同一个输出目录；工作台不会把浏览器目录句柄转换成系统路径，也不会静默覆盖同名日报。
- **知识库：** 点击“选择 Obsidian 知识库”会打开系统文件夹选择器，并显示所选完整路径。结构检查只核对目录名；标准目录齐全不代表旧笔记已被识别。研究记录、文献、RSS 和历史归档可分别关联库内已有笔记文件夹，不搬动、改名或覆盖原件；每次关联变更都会撤销该项读取授权，须重新确认。补齐标准目录仅新建缺失的空文件夹。桌面版在本人确认授权时保存库位置、关联目录及精确范围，重启后一键核对恢复；断开立即清除本次连接和保存记录，“忘记上次路径”只删除保存记录。
- **检查更新：** 桌面版检查 GitHub 最新发布版本，并提供 Windows 安装包和更新说明；网页开发版仍比较仓库 `main` 并复制安全更新指令。

## 成果预览（2026-10-01 源码首版，尚未发布安装包）

设置增加“成果与预览”：选择一次实际输出目录并启用只读预览。桌面版将目录身份、授权与手动文件关联保存在本机应用数据中，重开自动核对；开发服务仅保留本次运行连接。成果连接独立于 Obsidian，不扩大原知识库读取范围。

各研究任务顶部显示本任务成果。点击成果卡，在右侧文件面板查看，支持多标签、展开、收起、返回任务和宽度调整。PDF 用本地 PDF.js 翻页与缩放，图片直接显示，Markdown/TXT 本机阅读，HTML 做禁用脚本与外部资源的离线预览。PPTX/DOCX 使用同版本 PDF 或单张图片预览，保留可编辑原件；缺预览、文件移走和大小超限分别提示。HTML 内部滚动位置暂不恢复，PDF、文字与图片恢复外层阅读位置。

连接后，任务启动语带入 `<成果根目录>/<任务编号>/` 和 `danta-artifacts.json` 交付约定。清单须先有实际文件，原件和预览件属于同一版本；回到任务或点刷新时检查该任务清单，不扫描整个知识库。已有成果通过原生选择器关联，只允许选已启用成果目录内的文件，不移动原件；Office 原件可另选同版本预览件。关闭标签只关闭视图。

预览内填写修改意见，点击“继续 Codex 修改”将原件、版本、页码和意见交给已有交接弹窗，进入原对话后仍需粘贴并提交。意见定位不随翻页悄悄变化。预览标签、页码、缩放、外层阅读位置和意见保存在对应任务卡，随任务自动备份；原件与手动文件关联保存在原成果目录及单独本机连接记录中，任务 JSON 备份不携带原件或目录授权。换电脑需重新选择成果位置并关联已有文件。

成果服务位于 `server/artifactService.js`，前端集中在 `src/features/artifacts/`。桌面构建内置 PDF worker、字库、字符映射与 WASM；预览不从公网 CDN 加载研究文件。当前只完成本机代码与构建，Windows 实机生成、修改与重开全流程尚未验收，尚未上传或发布安装包。

## 返回与恢复

知识库子页面提供返回按钮，按进入页面的顺序回到上一个工作区。正式桌面版将任务、未完成草稿、引导内容、启动语、当前页面和弹窗状态自动写入本机应用数据中的 `workbench-state`；启动时先恢复磁盘状态，再显示界面。关闭窗口前会等待最后修改保存，保存失败时提示返回或仍然关闭。旧版浏览器草稿首次使用时迁移；浏览器开发预览仍使用 `localStorage`。设置中的“任务备份”既能导出/合并导入任务 JSON，也能在桌面版查看和恢复自动备份。最近一次版本单独保留，历史快照最多 10 份；按半小时变化留档，并在每次进程首次保存变化时留档，恢复前保存当前状态。损坏的主状态会尝试从有效备份修复；没有有效备份时保留原文件并报告错误。知识库路径和授权不保存在浏览器中；桌面版将其保存在本机应用数据，重开后须核对原知识库才能恢复。

## 当前数据边界

研究任务卡、任务内容、关联文件名、PPT 模板/Logo 选择、未完成启动语及关联的 Codex 对话编号保存在本机桌面应用数据中，退出重开可恢复，不上传云端。浏览器存储只作为兼容缓存；磁盘自动备份不包含 API Key 或知识库授权。旧版工作区草稿会复制迁移为任务卡，旧数据保留。工作台只记录关联文件名，不读取文件内容；任务卡状态不会自动从 Codex 对话同步。任务卡与 Obsidian 不自动同步。连接知识库并开启归档写入后，可在任何阶段点击“保存阶段记录到 Obsidian”，新建一份含任务内容、成果与来源索引、版本、未决问题和下一步的 Markdown；每次保留新版本，返回路径记录在任务卡中。保存不要求个人审核或任务完成，也不改变任务状态；仅引用成果位置，不读取或复制成果文件。正式研究记录仍按既有流程由主 agent 保留来源与证据状态后写入 vault。桌面版在本人确认时将知识库路径、关联目录及每项授权的精确路径保存在本机应用数据中，重开后核对库位置与目录仍一致才恢复；页面只在进入对应模块时读取授权目录。归档写入另有单独授权，且只新建文件。工作台不会读取 Codex 历史对话。任务交接优先提供“继续原对话并复制启动语”；另开新对话作为次级入口，任务卡保留历史对话编号。交接失败保留启动语和已有编号，不把窗口打开失败显示为成功。也可从对应工作区创建新对话并携带任务快照；新对话不预填输入框，打开后需按 `Ctrl+V` 粘贴，再由使用者检查并提交。工作台不会代为发送启动语。

启动语预览会包含任务名、目标、阶段、状态、下一步、待确认问题及关联文件名。工作台只生成并复制文字；只有龚博士手动粘贴并提交后，这些内容才会发送给 Codex。

## 维护者开发与打包

```bash
npm install
npm run check
npm run start        # 浏览器开发模式
npm run dist:win     # Windows x64 安装包
```

安装包通过 GitHub Actions 在 Windows runner 上构建。推送 `workbench-v*` 标签会创建包含安装程序和 SHA-256 校验值的 GitHub Release；用户从发布页下载，无需访问源码仓库。
