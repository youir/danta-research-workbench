# 龚博士科研工作台 · Windows 桌面版

工作台以 Windows 桌面程序分发。安装后从桌面或开始菜单打开独立窗口；网页界面、本机 Obsidian 桥接和 Codex 交接服务随程序启动。Codex 仍是实际的科研协作入口；工作台不会自动发送启动语，也不会自动执行 Git 更新。

## 给龚博士安装与日常使用

打开 [GitHub Releases](https://github.com/youir/danta-research-workbench/releases)，选择 tag 以 `workbench-v` 开头且版本号最高的桌面版，下载 `Danta-Research-Workbench-<版本号>-x64-Setup.exe`，运行安装程序。安装时可以选择位置；安装程序会建立桌面快捷方式和开始菜单入口。之后双击“龚博士科研工作台”即可打开，不需要克隆仓库、安装 Node.js 或打开终端。

桌面程序需要 Windows 10/11 x64。要使用“创建 Codex 新对话”等交接能力，本机还需安装并登录 Codex 桌面版，同时让 Codex CLI 可被本机识别。程序会从 Windows `PATH` 和 `%APPDATA%\npm` 查找 `codex.exe` / `codex.cmd` / `codex.bat`；若安装在其他位置，可设置用户环境变量 `CODEX_CLI_PATH` 指向该程序。安装或修改环境变量后，重新启动工作台。

桌面程序将本机服务绑定到 `127.0.0.1:48921`，只接受工作台自己的本机来源，不向局域网开放。若此端口被其他程序占用，先关闭占用程序再重新打开工作台。

顶部“检查更新”会查询 GitHub 桌面版发布记录。发现新版后，下载并运行安装包即可覆盖更新；本机草稿会保留。桌面版把已确认的知识库路径、目录关联和具体授权范围保存在本机应用数据中。退出或更新重启后，一键核对并恢复原范围；目录变化或知识库被替换时暂停受影响的授权。

完整的首次部署和数据说明见[桌面版安装与维护说明](桌面版安装与维护说明.md)。

系统各层职责与科研任务路由见[完整体系架构](../../08_完整体系架构.md)和[科研工作流与能力路由](../../docs/architecture/科研工作流与能力路由.md)。本机任务卡的数据维护集中在 `src/features/research-tasks/hooks/useResearchTasks.js`；页面入口负责导航、表单交接和本机服务调用。

## 页面结构

- **开始：** 写下一个研究问题，或进入选题、论文、PPT、组会准备 / 复盘、生物科研日报五个任务整理区。每次从入口开始都会建立独立的本机研究任务卡，允许同一类型并存多项。卡片可记录任务名、本次目标、研究阶段、状态、下一步和待确认问题，并保留该任务的草稿、工作台记录的文件名和 Codex 对话编号；首页可恢复到对应工作区，也可重新打开该任务关联的 Codex 对话。研究阶段和状态由龚博士手动维护，工作台不读取 Codex 历史或自动判定任务完成。科研 PPT 按“整理汇报任务 → 选择模板与单位标识 → 检查启动语”的顺序准备；内容区可选汇报形式、目标、听众和时长，再插入可编辑的填空框架，补充主题、真实材料、希望讨论的问题及待确认信息。所有引导项都可跳过，框架提醒只依据实际提供的研究材料整理，不推测或补造结果。工作台不预填具体病种、实验发现或研究结论。提供四套病理科研汇报模板的封面预览和 PPTX 下载，所选模板名及文件路径会写入启动语。可选内置海军军医大学或复旦大学上海医学院 Logo，也可选择暂不添加或在 Codex 对话提供其他获授权的标识。未选时，启动语会先引导确认实际汇报单位。首页的连接状态入口直接打开知识库说明，不代表已有研究记录。
- **研究记录：** 在知识库页明确授权“研究记录”后，读取两个标准目录及本人明确关联的现有文件夹中的 Markdown，显示标题、日期、摘要和相对路径；不会扫描未选目录。
- **机制图：** 单独入口，也能从 PPT 工作区进入。每次开启建立独立的机制图任务卡；从 PPT 进入时标记与 PPT 任务的关联，并带入前序内容、待解决问题、文件名与成果索引；两个任务各自保存，返回后恢复原任务。输入简短需求后生成绘图启动语；“查看制作过程”展开五步方法说明。BioTender 是可选技能索引，BioRender 是外部绘图平台，两个链接都不会携带研究内容。
- **文献与信息源：** 无需授权知识库即可输入公开 PMID，手动打开 NLM 的 PubMed Linked Discoveries 图谱；按该 PMID 发起查询，不附带本地文献资料。图谱用于探索相关文献与引文线索，不评价研究质量或复现成败。分别授权“文献证据”和“RSS 线索”后，可读取各自标准目录及本人明确关联的现有笔记文件夹；RSS 插件缓存仍只读本机已保存的数据，不刷新订阅或联网抓取全文。
- **归档：** 可按授权查看 `14_历史归档_Archive/`，或在明确启用“新建归档”范围后，填写标题和内容并新建 Markdown。只在 `14_历史归档_Archive/工作台归档/` 创建新文件，不覆盖或删除已有文件。
- **科研日报：** 可从日报页准备今日日报或 Codex 原生自动化的设置 / 暂停请求；工作台会创建 Codex 新对话并复制启动语，仍需在 Codex 中粘贴、提交并确认。自动化状态由 Codex 管理，工作台不读取开关状态。选择归档文件夹后可查看逐日报内容、来源与覆盖范围，并排版、预览和保存分享长图 PNG。浏览器记住所选文件夹句柄，再次打开时由用户授予本地读取权限；也可临时导入单份日报 HTML / JSON。Codex 工作区必须能访问同一个输出目录；工作台不会把浏览器目录句柄转换成系统路径，也不会静默覆盖同名日报。
- **知识库：** 点击“选择 Obsidian 知识库”会打开系统文件夹选择器，并显示所选完整路径。结构检查只核对目录名；标准目录齐全不代表旧笔记已被识别。研究记录、文献、RSS 和历史归档可分别关联库内已有笔记文件夹，不搬动、改名或覆盖原件；每次关联变更都会撤销该项读取授权，须重新确认。补齐标准目录仅新建缺失的空文件夹。桌面版在本人确认授权时保存库位置、关联目录及精确范围，重启后一键核对恢复；断开立即清除本次连接和保存记录，“忘记上次路径”只删除保存记录。
- **检查更新：** 桌面版检查 GitHub 最新发布版本，并提供 Windows 安装包和更新说明；网页开发版仍比较仓库 `main` 并复制安全更新指令。

## 返回与恢复

知识库子页面提供返回按钮，按进入页面的顺序回到上一个工作区。首页和任务工作区的未完成草稿、已填写的引导内容及启动语会保存在当前浏览器的 `localStorage`；刷新或重新打开同一浏览器后，首页会显示“继续上次工作”，可恢复未完成任务或重新打开启动语。清除浏览器站点数据会清除这些草稿；首页可导出任务备份 JSON，并在需要时合并导入。知识库路径和授权不保存在浏览器中；桌面版将其保存在本机应用数据，重开后须核对原知识库才能恢复。

## 当前数据边界

研究任务卡、任务内容、关联文件名、PPT 模板/Logo 选择、未完成启动语及关联的 Codex 对话编号保存在本机应用地址 `127.0.0.1:48921` 的浏览器存储中，退出重开可恢复，不上传到服务器。旧版工作区草稿会复制迁移为任务卡，旧数据保留。工作台只记录关联文件名，不读取文件内容；任务卡状态不会自动从 Codex 对话同步。任务卡与 Obsidian 不自动同步。连接知识库并开启归档写入后，可在任何阶段点击“保存阶段记录到 Obsidian”，新建一份含任务内容、成果与来源索引、版本、未决问题和下一步的 Markdown；每次保留新版本，返回路径记录在任务卡中。保存不要求个人审核或任务完成，也不改变任务状态；仅引用成果位置，不读取或复制成果文件。正式研究记录仍按既有流程由主 agent 保留来源与证据状态后写入 vault。桌面版在本人确认时将知识库路径、关联目录及每项授权的精确路径保存在本机应用数据中，重开后核对库位置与目录仍一致才恢复；页面只在进入对应模块时读取授权目录。归档写入另有单独授权，且只新建文件。工作台不会读取 Codex 历史对话。任务卡可重新打开关联的 Codex 对话，或从对应工作区创建新对话并携带任务快照；新对话不预填输入框，打开后需按 `Ctrl+V` 粘贴，再由使用者检查并提交。工作台不会代为发送启动语。

启动语预览会包含任务名、目标、阶段、状态、下一步、待确认问题及关联文件名。工作台只生成并复制文字；只有龚博士手动粘贴并提交后，这些内容才会发送给 Codex。

## 维护者开发与打包

```bash
npm install
npm run check
npm run start        # 浏览器开发模式
npm run dist:win     # Windows x64 安装包
```

安装包通过 GitHub Actions 在 Windows runner 上构建。推送 `workbench-v*` 标签会创建包含安装程序和 SHA-256 校验值的 GitHub Release；用户从发布页下载，无需访问源码仓库。
