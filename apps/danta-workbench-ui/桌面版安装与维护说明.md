## 手动安装与启动

1. 打开 [GitHub Releases](https://github.com/youir/danta-research-workbench/releases)，选择 tag 以 `workbench-v` 开头且版本号最高的桌面版，下载 `Danta-Research-Workbench-<版本号>-x64-Setup.exe`。
2. 运行安装程序，可选择安装位置。安装程序会添加桌面快捷方式和开始菜单入口。
3. 从桌面或开始菜单双击“龚博士科研工作台”。日常使用不需要克隆 Git 仓库、安装 Node.js、运行命令或启动浏览器。
4. 首次使用 Codex 交接前，确认电脑已安装并登录 Codex 桌面版，并能从本机找到 Codex CLI。工作台会在已安装的 Codex 工作区中创建新对话；复制的启动语需要龚博士粘贴、检查后亲自提交。

程序从 Windows `PATH` 和 `%APPDATA%\npm` 查找 `codex.exe`、`codex.cmd` 或 `codex.bat`。若 Codex CLI 在其他位置，可在 Windows 用户环境变量中设置 `CODEX_CLI_PATH` 为其完整路径，然后重开工作台。该电脑无需为工作台安装 Node.js；Codex 自身的安装与登录仍由用户按 Codex 官方流程完成。

## 更新桌面版

在工作台顶部点击“检查更新”。如果有新版，下载提示里的安装包并运行，安装程序会更新当前桌面版。任务草稿和已保存的模板选择保留在本机。新版在本人确认后保存知识库位置、关联目录和精确授权范围；更新重启后点击“核对并继续使用上次知识库”，只在原路径和目录仍匹配时恢复原授权。旧版保存文件没有授权范围，首次升级仍须确认一次，之后无需反复勾选。知识库位置或目录发生变化时，按页面提示修复受影响的范围。

维护者在已审查的版本提交上创建并推送 `workbench-v*` Git 标签后，GitHub Actions 会在 Windows runner 构建 x64 安装包，生成 SHA-256 校验文件，并将两者发布到对应 GitHub Release。该标签前缀让桌面应用能与知识库发行 ZIP 使用同一个仓库；不要把构建产物或研究档案提交进源码仓库。

## 配置 Jev

打开桌面版工作台，进入“设置 → Jev API Key”。粘贴密钥后点“保存并验证”。**绿灯**表示密钥曾通过一次真实 TypeSafe API 请求验证，并显示成功时间；**红灯**表示未配置或最近一次验证未通过。网络断开、额度变化后可点“重新验证”。验证只发送固定的英文示例句，不发送知识库内容。密钥由桌面应用用系统加密能力保存在本机，不会写进仓库或在界面回显。

如果龚博士希望通过 PowerShell 输入，只在**新版工作台已打开**时，在她自己的电脑上粘贴以下整段命令。命令会隐藏密钥输入，密钥不会出现在命令历史中；提示出现后再输入密钥并按回车。不要把密钥发到聊天里，也不要把密钥直接写在命令文本中。

```powershell
$secure = Read-Host '请输入 Jev API Key（输入不显示）' -AsSecureString
$pointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secure)
try {
  $payload = @{ apiKey = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($pointer) } | ConvertTo-Json -Compress
  $result = Invoke-RestMethod -Uri 'http://127.0.0.1:48921/__danta/jev/configure' -Method Post -ContentType 'application/json' -Headers @{ Origin = 'http://127.0.0.1:48921' } -Body $payload -ErrorAction Stop
  if ($result.verified) { 'Jev 绿灯：密钥已保存并验证。' } else { 'Jev 红灯：密钥已保存，但本次验证未通过。请在工作台设置里查看原因。' }
} catch {
  '未能完成配置。请确认新版工作台已经打开，再到“设置 → Jev API Key”查看或重试。'
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($pointer)
  Remove-Variable payload, secure -ErrorAction SilentlyContinue
}
```

这个绿灯仅说明工作台能连接 TypeSafe API。Codex 内的 Jev MCP 另有工具连接；若 Codex 未加载该工具，科研引导会按原有检索流程继续，不能把工作台绿灯当作 Codex 工具已可用。

## 本机数据与权限

- 桌面应用及本机桥接仅绑定 `127.0.0.1:48921`。该端口只接受工作台同源请求，不向局域网开放；若被占用，关闭占用程序后重试。
- 任务草稿保存在桌面应用的本机浏览器存储中，不上传。卸载程序默认保留这些用户数据；在 Windows“设置 → 应用 → 已安装的应用”中卸载工作台不会删除 Obsidian 知识库或 Codex 工作区。
- 本人确认的 Obsidian 路径、目录关联和读取/归档授权保存在本机应用数据中，不写入 Git。恢复前核对文件夹身份与具体范围；关联目录失效时只暂停该项。结构检查只读目录名称；补齐操作须经确认，只创建模板缺失的空文件夹，不会移动、改名、删除或读取现有笔记和附件。页面按用户逐项批准的范围读取指定目录，归档另行授权且只新建文件。点击“断开并清除本机授权”会删除保存记录。
- 工作台不读取 Codex 历史对话，不自动提交 Codex 启动语，不自行更新 Git 仓库。
