# 技能路由与能力边界

先明确本轮要推进哪个思考问题，再决定是否调用技能。问题可通过一次澄清解决时，不为调用工具而检索或产出长报告。上游的头脑风暴、评估和写作流程应服务于人的思考；有分歧时保留分歧，不能用自动排序替代她的决定。

本包提供独立的主引导技能和七个固定版本的 GitHub 科研技能。先核对安装日志/环境报告；能找到文件不代表全部脚本依赖已配置。

| 当前任务 | 读取的上游技能 |
|---|---|
| 生成和整理候选问题 | scientific-brainstorming |
| 文献检索、筛选与证据矩阵 | literature-review |
| 证据、偏倚和推论审查 | scientific-critical-thinking |
| 观察转成可检验假说 | hypothesis-generation |
| 终点与统计分析规划 | statistical-analysis |
| 研究目标、论证结构和进度 | research-grants |
| 用户自己的方案与草稿评审 | peer-review |

优先按任务读对应 SKILL.md，再读其引用的必要文件；不要一次加载七套手册。不需要强制创建子代理。上游如提到本包未附带的其他技能或 API，先核查是否确实需要，不能说已安装。

若上游流程需要额外付费检索、AI 绘图、文档引擎或 API Key，先说明缺口。当前任务能用现有工具完成的，明确使用“借鉴该方法的简化流程”，不要声称已完整执行原 skill。研究准备度不依赖作图服务可用；不把上传资料或注册外部服务当成默认授权。

research-grants 的特定资助机构格式不替代学校开题要求；peer-review 用于用户有权处理的自身方案，不代表真实期刊评审；统计建议须与研究设计匹配。主引导负责状态与阶段；上游负责具体任务方法。
