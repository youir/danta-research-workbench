# 内容版本与更新

Git 源码、桌面软件版本、当前工作区已加载技能是三个状态。Git 更新不自动改写私有 vault 的 `.agents/skills`，桌面升级也不等于 Codex 技能更新。源码内容版本见 content-version.json；安装记录保存在技能目录的父目录 `.danta-skill-receipt.json`，每个技能记录版本与文件校验值，不能仅凭路径存在声称最新版。

## Codex 协助维护的最短流程

1. 定位本人实际使用的唯一私有工作区和主技能，避免全局与项目内两份同名技能竞争。检查项目内技能优先，再按实际客户端加载行为确认；不要更新两个位置后宣称都在使用。
2. 在本人已要求更新时，取得核对过的发行源码，不在真实研究库执行 Git reset/clean 或覆盖模板。Windows 用 `py -3`，其他系统用实际 Python 3.9+。
3. 从发行目录运行 `python3 scripts/update_skills.py --dest "<唯一工作区>/.agents/skills"`，先只读比较。默认主引导及其依赖，不安装整套 vendor。
4. 若旧版没有 receipt，可从已核对的旧发行 tag/commit 取旧 MANIFEST.json 到临时文件，使用 `--baseline "<旧清单>"`。仅旧文件与旧校验值完全一致才可更新；来源不明或有本人修改的目录保留，逐文件比较后再处理，不提供强制覆盖。
5. 确认无冲突后加 `--apply`。备份留在技能发现目录外的 danta-skill-backups；复制后校验，异常回滚已替换的技能。receipt 只记录受管理内容，无密钥。需要回退时按备份及原 receipt 恢复，不把备份复制回 skills 目录成为第二个技能。
6. 新开对话读取该工作区新版主引导，报告内容版本、真实加载情况及未完成项。安装完成不能替代首次真实工具验证。

## 私有库升级边界

更新器仅替换校验一致的受管理技能。Path-Map、本人授权、笔记、AGENTS、Codex/Jev 配置不被模板替换。新规则需私有库入口引用时，将 AGENTS 中对应少量段落与新版比较合并，保留本人规则；新增授权记录从空表建立，不能填造授权。已有路径可由 workspace_context 工具逐项注册/切换，未切换时继续兼容旧 schema。

用户没有提出升级，不后台更换技能。系统目录/凭据修复沿用已授权范围；不把内容更新当作重新授予全部资料权限。桌面应用发布由原工作台安装/更新流程完成，本脚本不安装 EXE、改变应用状态或迁移研究文件。
