# 组会：为讨论与研究决定准备材料

触发：准备组会、文献汇报、导师讨论、进展汇报、困难汇报、预答辩、整理会后反馈。先读取当前状态、Idea、OGSM、上次组会未闭环与相关证据/实验记录；vault模式一律按Path-Map解析旧路径。不要为了组会重新创建文献台账。

## 先确定这次需要讨论什么

从已有材料识别汇报类型：文献讨论 / 选题讨论 / 方案评审 / 进展更新 / 困难求助 / 预答辩，可混合。听众、时长、截止时间、导师要求未知时，只问会改变组织方式的关键项；没有答复时可给明确标注假设的提纲，不虚构安排。通常围绕一个主问题和少量需要判断的事项。

文献少、实验失败、尚无结果也能准备组会。用“目前知道什么、为何受阻、什么证据能区分原因”组织，不编进展，不以阅读篇数或页数补足内容。不自动每周检索或创建后台任务。

## 形成可追溯的讨论包

用 `我的开题/10_组会与复盘/` 中空白模板起稿。每次组会用 MEET-编号及实际日期建独立目录或文件，状态为会前草案/已讨论/已核对，保留历史。模板不覆盖上次已填写的包。

1. 会前讨论单：当前问题、上次基线及决定ID、本次变化、证据位置、仍有的分歧；每个请求帮助的事项列可选路径、取舍、资源限制和本人暂时倾向。倾向不等于已决定。
2. 证据增量：按 literature-update.md 更新同一文献记录，筛出真正改变判断的材料。实验进展引用EXP/DATA/RUN/FIG及版本；仅有口头自述时标明来源。
3. 汇报提纲与口头摘要：按时长调整，不固定10–12页。每页只有一个讨论目的，写“页标题、核心信息、证据或图表ID/位置、阅读范围、讲述要点、估计时长、引出的讨论”。标题不能强于数据。主讲与问答分开留时间；预计时间标为估计。
4. 会前核查：数字、图表、研究单位、引用、结论边界与待判断问题逐项检查。只有题名/摘要的研究不称全文精读。没有可用图表就明确缺口，不生成假数据图。
5. 模拟提问：区分材料可以回答的问题、需现场向导师请教的问题、尚待核查的问题。拟答引用来源；不知道时说明怎么补证据，不能代拟导师同意。

默认交付Markdown讨论包和PPT逐页提纲，不声称已生成.pptx或实际演讲。用户要求实际演示文件时才使用可用演示工具，核实图表和排版。短任务可合并交付为一个文件，不要求写全套表。

## 不同类型的重点

- 文献：为何选这篇、问题/设计/实际结果/局限、如何改变我的课题；多篇比较只在有可比依据时合并，分歧不硬凑趋势。
- 选题：关键现象、竞争解释、已有与缺失证据、最小区分性验证、需导师判断的边界。
- 方案：问题→研究单位/对照/终点→证据路径→可行性与替代路径，先暴露设计不足再讨论修正。
- 进展：相对上次基线的变化、实际完成/未完成、结果及不确定性、对OGSM的影响。待做实验与已有结果分开。
- 困难：原预期、实际观察、已排查及依据、可能原因、下一步最小排查、希望获得的资源或判断；不把阴性结果一概认定为技术失败。
- 预答辩：学校要求、问题—设计—证据—结论的一致性及关键缺口；开题尚无结果时使用计划和不同结果的含义。

## 多 agent 与人的发言

已选择多agent时沿用现有协议：文献角色核查来源和新旧证据；方法角色核查单位、对照、分析及可行性；质疑角色检查过强结论与真正应讨论的问题。返回当前MEET ID和方案版本；主引导合并。不为每页启动agent，不把一致意见当新证据。女娲仅补模拟视角，实际导师反馈以用户提供记录为准。

## 会后闭环

先区分真实记录中的原话/转述、研究者理解、AI建议和待确认内容。仅当会议实际发生且有资料时整理会后纪要；没有反馈就停在会前准备，不编导师要求。

明确决定引用已有决策日志或新增DEC；行动沿用事项ID，写执行人（未确认可空）、时间或触发条件、完成判据、所需证据。模糊表述如“看看这个方向”只列待澄清，不标批准选题。只更新实际受到影响的OGSM、方案、状态与未闭环；记录旧/新版本、理由、来源和未改项。没有明确选择时可以保留草案继续探索，不反复征求形式确认。

最后保存组会索引和必要的会话交接。稳定经验进入Wiki/记忆并附来源；不把整份PPT、聊天或导师推测再复制成长期事实。准备汇报不授权发送给导师、上传外部服务或发布研究资料。
