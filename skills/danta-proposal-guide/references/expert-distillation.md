# 女娲专家顾问接入规则

只有用户要求蒸馏、创建/更新人物视角或寻找思维顾问时，读取已安装的 `huashu-nuwa/SKILL.md`，按原流程执行；一般开题讨论不自动开启蒸馏。本文件只做Codex路径、并发与科研用途适配，不替代女娲正文、模板或检查点。固定来源见工作台第三方说明。

## 原流程与交付

以下六维、人物模板与立场测试描述针对人物路径。主题路径严格按女娲「特殊场景 > 主题Skill」覆盖相应阶段：Phase 0A确认主题边界/受众；Phase 1先找3—5个核心人物或流派，按人物分工而非一人六维；提炼共识框架与流派分歧，采用中性专业表达；Phase 3去掉人物角色规则/身份卡，改用框架概览与流派对比；Phase 4对照领域经典案例验证。主题不伪装成某位专家。原检查点和自包含保存仍保留。

- 明确人物/主题走Phase 0A；只有模糊需求走0B，先诊断并给2—3个差异化候选，由使用者选择。支持新建、增量更新、人物或主题框架。
- 保留原档位：快速3维（著作/对话/表达，各最多5来源）；标准6维；深度6维加一手素材采集。先说明成本量级，已有选择不重复问。原文所述金额是历史例子，不能当作当前Codex报价。简单“就做某人”可按上游默认标准档推进，但明确默认；素材和预算缺口不靠编造补齐。
- Phase 0.5创建自包含目录。Phase 1按本地优先/纯网络/纯本地模式采集，六维分别为著作、对话、表达、他者、决策、时间线（包括最近12个月）。快速档未做维度明确记未开展，不伪造六维完成。
- Phase 1.5按原文展示调研质量摘要，等用户确认或补充要求；Phase 2读取 extraction-framework，做跨域复现、生成力、排他性三重验证，提取心智模型、启发式、表达DNA、价值观/反模式/张力、智识谱系、诚实边界。Phase 2.5展示提炼摘要等确认，再构建。
- Phase 3使用原 skill-template，保留角色边界、防漂移、归属链接及根据模型推导的回答工作流（问题分类→按人物模型研究事实→回答）。不得把普通背景介绍当成完成蒸馏。
- Phase 4独立执行3道已知立场题、1道边缘题、约100字风格样本；遵循原通过标准和最多两轮回修。展示验证结果请使用者确认。再按Phase 5用两个独立agent做结构/触发与可执行性精炼，合并无冲突修改，展示变更摘要请确认。不能把脚本PASS当作这些过程已发生。
- fidelity-scorecard用于评分报告时，答题与评分必须独立，出题不泄露答案；记录真实模型信息，无法获得就标未知，不伪造。它检验人物视角表现，不证明科研判断正确。

确认只针对已经可审阅的调研/提炼/验证/变更结果；等待时可继续独立的整理工作，但不跨越依赖该确认的阶段。询问时指出女娲SKILL.md相应Phase与原文要求并链接实际文件，不把这套确认机制扩展到普通开题对话。平台不能独立执行验证时，记录“独立验证未运行”，交付中间产物，不宣称严格全流程完成。

## Codex路径与派工（显式适配）

上游`.claude/skills/`为宿主示例。在Codex，仅检查用户指定工作区内的顾问目录和当前客户端已配置技能目录；不扫描父目录、私信或云盘。新顾问默认放在私有工作副本的 `.local/advisors/<person>-perspective/`；主题用 `<topic>-framework/`。不把真实材料写进公开仓库或vendor。提供给用户的原材料只复制，不移动。

每个顾问目录含SKILL.md、scripts/、references/research/、references/sources/{books,transcripts,articles}/；保留原01—06调研文件命名。阶段状态、确认记录、测试结果、日期及来源索引也保存在顾问目录内部，更新时保留历史，不重写整套。

保留六个职责，服从客户端并发上限：当前工作台最多3个专家并发，分两批执行；不能并行时按女娲降级表逐维串行，每维完成即落盘。不得把六个职责说成六个同时执行。只使用真实已返回的任务ID等待。

这是普通只读专家规则的限定例外：经用户启动蒸馏后，可给通用调研agent明确的单个 `references/research/0X-xxx.md` 写入权限及必要素材子目录；不同agent不写同一文件，不改主SKILL或个人研究记录。若只能调用本包只读角色，则改为女娲允许的主agent逐维串行落盘，不让只读角色假称写入。主引导负责整合与确认记录。Phase 5两个评审各自返回建议，由主引导修改。

为避免运行时版本检查修改发行包，使用已安装的huashu-nuwa；未安装时先按包内离线安装器安装，或将该运行目录完整复制到工作副本.local中再显式读取。运行产生的 `.last-update-check` 只是日期缓存，不随发行包发布、不触发自动升级；更新仍固定版本并保留原记录。

## 科研顾问的使用

首次激活遵循原模板，明确“基于资料提炼的模拟视角，非本人意见”；未公开表态的主题标框架推断，关键事实与原话保留出处。可以按原模板使用第一人称，但不能冒充已联系专家、获得真实导师同意或得到机构认可。

顾问用来提出新解释、核查论证和帮助她判断。多个顾问赞同不构成新增证据，人的选择不自动转为专家真实立场。本人论文中的共同作者结论不自动等于其个人决策习惯，重复表述不证明真实内心信念。保留女娲的信息源选择、矛盾和不足处理规则；不足时按上游降级而非填满数量。

非公众人物按女娲要求仅用用户提供素材，并提醒取得当事人同意；“只用本地”时不搜索本人或将素材上传到额外服务。本地文件仍可能由当前Codex模型处理，不能声称离线推理。仅保存有权使用的原文，来源下载遵守访问权限，不因上游列出某网站就绕过访问控制。人物产物和原始语料不会随系统更新上传；单独发布需要另行明确范围。

## 配套脚本的边界

保留原始 quality_check.py、merge_research.py、srt_to_transcript.py、download_subtitles.sh。前三个是Python标准库脚本；字幕下载需要bash/yt-dlp和可访问的视频字幕，按需配置。安装器不执行下载或开通服务。

quality_check与merge_research按文本模式/关键词计数，不是真实一手来源比例、研究质量或语气保真度的证据。来源必须按去重后的实际材料人工/agent复核。下载脚本使用临时标记和已有文件查找，不应只凭退出码判断成功；核对输出对应当前URL和新文件。字幕清洗会移除时间戳，保留原SRT/VTT以便追溯。
