# 工作区接续：授权、课题与任务深度

## 恢复已有授权

核对唯一私有工作区及 `00_系统_System/06_授权范围_Access-Scope.json`（旧工作区可用根下同名记录）。记录是实际人类授权的索引，不产生系统权限。沿用此前对话、应用中本人确认的范围或已核验记录，写明来源、原意与日期；AI 建议、代理报告和模板不等于授权。

路径、资料类型、用途、保存位置、处理服务未变化且未撤销时，不因重新打开或切换对话重复确认。如果本人明确同意长期处理同一目录的新增文件，记录 include_future_files=true；一次扫描则为 false。新增文件仍须符合类型、用途和排除项。范围变化只核对新增部分；用户撤销即停用。

路径丢失、移动或系统权限失效时先诊断并恢复既有连接，不能恢复才请本人定位或操作系统界面。不扩大到父目录，不重新要求全套授权。桌面应用的持久授权与本记录按真实来源核对，不能互相伪造状态；本规则不改写系统、Codex 或前端的权限机制。

## 活动课题统一解析

Path-Map 是唯一活动课题来源，根 marker 的旧 active_project 仅作兼容信息。写入前运行本技能 `scripts/workspace_context.py --workspace <vault>`，获取活动课题ID及解析后的 roles/paths；它只读 marker 与映射，不扫描研究内容。

注册已有课题：`--register P002 --project-root 05_课题项目_Projects/01_新课题 --title 课题名称`；切换：`--activate P002`。由 Codex 代执行。注册只收录库内已有目录，先按需要建立该课题空白状态、思路、决定等文件，不从真实主课题复制内容。`--dry-run` 先看变更；写操作备份旧映射并单文件原子替换。

切换同步原课题下所有 paths/roles，不只改 active_project。缺文件报告缺失，不回退其他课题同名文件。旧 schema 1 兼容；注册后升级。多课题分别保存状态、假设、资源、决定与分析；授权不会因换库迁移。

文献身份和逐篇证据可共享；主张、用途、组会、输出和记忆注明 project ID。证据导航用“课题ID + 主张ID”关联输出路径及位置；同论文多次引用不算多份独立证据。通用协作偏好可共享，课题推断与资源不能套用。通用模板 project 留空，实际记录填所属课题。

## 按任务需要留记录

| 任务 | 交付 | 必要记录 |
|---|---|---|
| 概念解释、单段修改、翻译、图注 | 答案或文本 | 没有长期变化就不落盘、不填卡 |
| 文献问题、组会、普通研究协助 | 结果、关键来源及阅读范围、下一步 | 只更新相关证据/成果及有变化的状态 |
| 方向选择、方案实质变化、证据推翻旧判断 | 依据、条件、影响及待解决问题 | 真实决定与受影响记录；AI 提议保留身份 |

不以完成模板、批准长计划或重复画像访谈作为启动条件。少量任务不强制多 agent/Jev。已有清楚授权和选择直接落实；缺失信息会实质改变结果时才问。
