# 研究步骤：任务、过程与成果接续

组织关系为“课题 → 研究任务 → 实际步骤 → 成果”。一个阶段可有多个步骤，一步也可同时使用实验和生信证据。龚博士描述当前目标即可；主引导只为实际开始的材料处理、分析、制作或长讨论建立步骤。普通问答、尚未决定的路线不预建文件夹，不要求本人填写完整过程表。

## 建立或接续

先恢复唯一私有工作区、有效授权与活动课题。标记 vault 按 Path-Map 解析课题，步骤位于该课题的 `07_研究步骤_Steps/`；旧工作台用 `我的开题/11_研究步骤/`。已有步骤属于其他课题时定位原课题，不随活动课题切换复制它。

调用随技能安装的 `scripts/create_research_step.py`，先 `--dry-run` 查看位置，再执行：

```text
python create_research_step.py --workspace "<确认后的私有知识库>" --title "<本步名称>" --goal "<本步目标>" --task-id <工作台任务编号> --step-key <工作台步骤键> [--project-id <原课题编号>] [--artifact-dir "<已配置成果根目录>/<任务编号>"]
```

- 前端启动语已携带任务编号和步骤键，必须原样使用，标题或目标不充当身份。重试复用同一键；再次开展不同工作，在前端添加新步骤取得新键。`--project-id` 在恢复原课题时使用。
- 直接与 Codex 对话、没有前端任务时可省略 `--task-id` 与 `--step-key`。相同名称及目标才复用；目标或输入已明显改变时使用 `--new` 并链接前一步。不为使用该脚本额外制造前端任务。
- 默认只建当前步骤、索引与轻量记录。文件先在临时目录完整生成，再发布步骤目录；半成品旧目录不静默复用或覆盖，同键重复记录先核对。索引更新失败可用同一命令重试。
- 原始数据、文献、唯一当前状态、证据矩阵和决定保留原位。步骤只记录实际输入位置、真实动作、产物版本、阻塞与下一步；只有本轮需要的内容才补充。

```text
07_研究步骤_Steps/00_index.md
  STEP-0001-简短名称/
    00_index.md
    00_步骤卡.md
    01_输入_Input/00_输入索引.md
    02_过程_Process/00_过程记录.md
    03_产出_Output/00_产出索引.md
    04_核查与交接_Review/00_核查与交接.md
```

每个子目录同时有 `00_index.md`；Markdown 含标准 frontmatter，供 Obsidian 和知识库校验兼容。新建卡的 status 为 planned，不能凭目录存在记为“已执行”。

## 工作台同步约定

前端步骤卡先是本机草稿，进入 Codex 后才建立知识库记录。脚本生成 `00_步骤卡.md` 的平面头部：`danta_step_schema: 1`、`project_id`、`task_id`、`step_id`、`step_key`、`title`、`goal`、`status`、`next_action`、`updated`。文字使用 JSON 双引号转义（合法 YAML 字符串），保留字段名，不放多行值或重复键。

主引导按实际进度更新 status（planned / in_progress / waiting_input / complete）、next_action 与 updated。完成仅指本步，不代表整个任务完成或科学结论验证。知识库步骤卡是同步进度的权威记录，前端任务卡是本机接续入口。

前端进入任务或回到窗口时在已有“研究记录”范围内只读匹配的步骤卡；“同步记录”可手动刷新。“查看过程”只读取本步五个约定 Markdown 文件，不读取输入原件、附件或任意索引链接。路径不在已授权研究记录范围内时，保留本机索引，说明尚未核对；不暗中扩大权限。同一任务、同一步骤键出现多份记录时停止匹配并列出冲突，不能猜最新一份。

旧的无任务键步骤不自动挂到前端任务。确需关联时主引导先核对确属该任务、备份原步骤卡，再补充头部和缺失索引；不迁移原始资料或替换已有过程。

## 成果路径

涉及生信或统计实际执行时，再读 [bioinformatics-delivery.md](bioinformatics-delivery.md)。输入类型、物种、样本单位、比较与交付要求只补充本步需要的内容；来源 JSON 与该版本成果同目录保存，在产出索引链接它，不另建一份运行事实。前端材料线索不代表已读取，来源 JSON 的报告状态也不代表工作台重新执行或科学验证。

已配置成果目录时，原件和同版本预览统一放在 `<成果根目录>/<任务编号>/`，按启动语更新 `danta-artifacts.json` 并保留旧版本。`03_产出_Output/00_产出索引.md` 只登记这些原件的实际位置、版本、来源和待核查项；不要再复制一份到步骤目录。没有前端成果连接时明确实际交付位置并记录索引，不假装前端已能预览。

交付或中断时，按需记录已核查、失败、阻塞和最小下一步；有实质变化才更新唯一课题状态、Idea 画布或决定。唯一当前状态链接当前步骤，步骤索引链接步骤卡。向用户说明实际文件位置与未完成项，下次从该步骤接续，不把计划记成已完成。
