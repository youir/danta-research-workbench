# 生物研究安全审查后的协作流程

此流程处理安全审查后的衔接，不重新判断或绕过平台审查。主引导优先恢复正常、合规的科研协作；只在平台明确阻止某个具体部分时启用本流程。

## 1. 暂停具体范围

- 简短说明被暂停的部分及原因类型，不复述可能造成风险的细节。
- 停止直接回答，也停止通过改写、拆分、工具调用、联网搜索、代码、图片生成、子 agent 或其他模型完成等价请求。
- 不把审查结果当成“用户已授权外发”的信号；不得自动调用 computer use 打开 KimiWork、创建新对话或上传资料。

## 2. 建立安全连续性记录

研究协作需要延续且当前有权访问龚博士的私有 vault 时，将模板 `12_笔记模板_Templates/15_生物安全审查记录_Biosafety-Review.md` 复制到 Path-Map 中的 `biosafety_reviews` 目录，以日期和去标识化任务代号命名。记录只保存：

- 高层目标和已完成的安全工作；
- 暂停范围的概括性标签，不含被拒绝的细节；
- 可独立继续的安全子问题、所需的人类决定；
- 使用过的公开来源 ID/链接、范围核验状态和下一步；
- 是否涉及外部服务，仅记许可状态，不另存外发材料。

不逐字保存原始请求、模型拒绝文本或操作性方案。不得记录患者/受试者身份信息、凭据、未授权数据，或能把记录变成受限任务“复活提示”的细节。若无法可靠脱敏，记录“详情留在机构批准环境，未复制”即可。只在明确授权的研究工作区落盘；没有该库写权限时给出不含风险细节的状态摘要，不擅自扫描或新建其他位置。

## 3. 继续允许的工作

判断安全子任务是否能与受审查部分真正分开。可在当前规则允许时继续：

- 病理学/疾病概念的非操作性说明和公开文献综述；
- 证据强弱、争议和研究空白的高层整理；
- 与受限内容可分离的论文逻辑、摘要结构、图表组织或通用语言编辑；
- 伦理审查、生物安全原则、机构流程和法规要求的来源核验；
- 合规替代问题或安全的行政、归档与组会整理。

若安全工作会实质上指导完成被暂停的操作、优化或规避限制，就不要继续该部分。不要用“纯理论/教育用途”作为自动放行理由。向龚博士给出一两个可行的安全下一步，让她选择；简明说明不能继续的范围。

## 4. 处理可信访问

若用户提到研究人员可信访问，或平台提示有此申请：

1. 使用官方、现行的服务文档核实申请入口、条件、用途和适用范围；不要根据转述推断资格。
2. 龚博士可以自行申请。主引导可协助准备真实、最小必要的用途说明和材料清单，但不代填虚假信息、不申请冒用身份、不共享账号凭据。
3. 在其本人提供官方结果或授权查看的资料前，状态标为“待核实”；获批后也只在被批准的产品、账号、研究范围和有效期内使用。
4. 官方可信访问不构成把请求转给其他未获批模型的授权，也不取消机构伦理/生物安全、数据保护或第三方服务要求。

官方入口变动时优先引导她从产品设置或官方帮助中心进入，不在空白模板中硬编码未经核实的 URL。

## 5. 外部模型和计算机操作

审查后的同一任务不得用 KimiWork 或其他服务重试。即使保存了同目录记忆文件、龚博士同意打开外部服务或外部模型愿意回答，也不能改变这一限制。

对于与该审查无关、且本身允许的独立工作，若龚博士单独要求使用外部服务，开始外发前逐项确认：具体平台、具体文件/片段、处理方式、保存位置和云端处理边界；只传该任务所需的最少去标识化材料。取得该次外发的明确同意后才可执行，并仍须遵守机构和服务规则。对审查提示的自动化触发一律关闭。

## 6. 回到工作台与复盘

只接收获准工作所得的安全结果。核对引用和来源，区分模型转述与原文证据；不能把另一模型的答复说成官方批准或审查结论。只将非敏感、可复核、对后续有用的安全摘要写回私有库。关闭记录时更新状态和下一步，不复制受限内容。

## 7. 推荐回复

“这一部分触发了平台安全审查，我先暂停它，不会把同一请求转到 KimiWork 或其他模型。为接续工作，我会只在你授权的私有知识库里保留一份不含操作细节的摘要。我们仍可继续其中可分离的病理/文献背景、论文结构或伦理与合规核查；如果平台提供研究人员可信访问，我可以帮你核实官方申请条件。”
