# 生信材料引导与可回看的分析交付

## 先判断本轮需要什么

她可以直接描述问题，也可在工作台“研究任务 → 当前实际步骤 → 涉及生信材料？补充线索”填写材料类型、位置/公开编号、物种、参考版本、样本与分组、比较目标和期望交付。字段可留空，已有有效授权和相关记录先恢复，不重新问整套问题。不把模板示例当作本人数据。

材料路径、编号和前端选择不是读取授权。涉及私人材料时沿用真实既有授权，首次或扩大范围再确认；说明本地文件内容是否会进入云端模型。只处理当前所需材料，不扫描父目录或整个磁盘。界面不会直接读取这些输入位置。

按输入区分：公开编号需要核实数据库、物种、数据层级及实际可下载资源；计数矩阵需要核对整数计数/标准化值、样本单位、设计与比较；单细胞/空间对象需要核对对象结构、细胞与生物学样本、批次、参考和已有处理；FASTQ 需要核对参考资源、计算资源、流程与依赖；已有结果先核对生成方法、版本和可用原始记录。仅问会改变当前行动的缺项；可先给带已说明假设的方案。

## 明确可执行条件

依次区分“可以讨论方案”“可以检查材料”“可以执行分析”。按任务检查真实 R/Python/分析工具版本、输入访问、资源及安装依赖。依赖未就绪说明具体缺口，不默认安装整套工具或下载大数据。材料检查和分析执行分别按实际授权开展。

真实执行前记录目标和输入索引；执行时保留实际脚本/命令、参数、环境、开始/结束时间、日志、退出码及产物。未记录的历史信息写未知，不倒填推测值；方案、示范、失败和正式分析分别说明。来源索引不代表已阅读全部内容。病理、临床和生物学解释须对应真实证据。

## 一次运行对应具体成果版本

在已获授权的成果目录保存原件、同版本预览、来源 JSON。步骤的过程/产出索引链接这些实际记录；不复制权威状态或原始数据。保留旧版本，先保存文件，最后更新成果清单。

`danta-artifacts.json` 的对应成果项增加可选字段：

```json
{
  "id": "<稳定成果编号>",
  "title": "<真实名称>",
  "version": "<本次版本>",
  "original": "<原件相对路径>",
  "preview": "<同版本预览相对路径，缺少则留空>",
  "provenance": "<该版本来源 JSON 相对路径>"
}
```

来源文件采用以下协议。以下是占位格式，不是已完成的分析；所有字段须换为真实记录，未知文字字段留空，未知退出码为 null。runId 使用一次实际运行的 UUID 或稳定编号（8–100 字符，字母数字、下划线或短横线）。

```json
{
  "schemaVersion": 1,
  "taskId": "<启动语中的任务编号>",
  "artifactId": "<清单中完全相同的 id>",
  "artifactVersion": "<清单中完全相同的 version>",
  "runId": "<实际运行 UUID>",
  "stepKey": "<当前步骤键，缺少则留空>",
  "status": "unknown",
  "exitCode": null,
  "startedAt": "",
  "endedAt": "",
  "method": "",
  "command": "",
  "parameters": "",
  "environment": "",
  "inputs": [],
  "scripts": [],
  "log": "",
  "checkStatus": "not_checked",
  "checkNote": "",
  "outputSha256": ""
}
```

- status 只取 succeeded / failed / unknown。真实成功必须 exitCode=0；真实失败必须已知非零退出码。没有可靠退出码用 unknown，不能按产物存在猜运行成功。时间使用真实 ISO 8601 时间，结束不得早于开始。
- checkStatus 只取 passed / failed / not_checked。checkNote 必须说明实际检查内容、范围、失败/未查项；不得笼统声称“科学验证通过”。没有实际核查用 not_checked。退出码 0 不自动把 checkStatus 改为 passed。
- inputs、scripts 每项只写与本任务相关的索引（最多各 30 项）；command 只保存去除凭据后的实际命令，environment 保存实际相关版本。日志原件在步骤或成果目录，只登记位置，禁止写入密钥、病人身份或无关私有路径。不得凭借索引自动打开任意文件。
- outputSha256 是最终原件字节的真实 SHA-256（64 个十六进制字符），不是预览件或清单的摘要。每个成果原件单独计算并登记。原件修改后生成新版本、新来源记录；同次运行可被多份成果引用。
- 来源文件必须为本任务目录内普通 JSON，最大 128 KB；文字字段尽量简洁。不得引用绝对路径、../、隐藏文件或符号链接作为清单里的 provenance 路径。

没有真实执行分析或无法核实历史记录时 provenance 可留空，旧成果继续预览。明确是手动导入的旧文件，不补造它的运行记录。

## 工作台如何展示

成果预览“来源与方法”按需读取本版本来源文件，校验任务、成果编号与版本匹配；展示报告的运行结果、报告的核查结果、方法、参数、环境、输入/脚本/日志索引。索引只显示，不执行或自动读取。

“核对当前原件”由本人点击后读取已授权目录内原件（最多 100 MB），计算摘要并与记录比较；说明核对时间。校验一致只说明本次读取的文件与记录一致，不能证明输入正确、方法合理、结论成立。大文件通过实际执行环境核对并保存说明，不伪造工作台检查结果。

Methods 只从实际方法、参数、环境和输入记录整理；缺失内容留待补充。统计关联、计算成功、生物学推断、实验支持及本人/导师决定分开表述。
