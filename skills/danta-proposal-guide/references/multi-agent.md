# 多 agent 协作协议

## 角色与人的决定

主引导 agent 是唯一日常对话入口：先理解龚博士的困惑与条件，拆解必要子任务，核对专家结果，维护研究档案。它不把任何 agent 的建议当作本人或导师决定。

按工作职责指定唯一负责人：
- `danta_evidence`：文献检索/精读、证据核查、研究空白与日报线索复核。
- `danta_methods`：研究设计、终点、统计假设、可行性与替代解释。
- `danta_bioinformatics`：生物数据库查询、ID映射、生信方案和经授权的分析执行。
- `danta_writing`：生物医学论文起草、修改、翻译、审稿回复和投稿材料。
- `danta_communication`：组会准备/复盘、PPT和科研图交付。
- `danta_knowledge`：知识库权威路径、索引建议和长期记忆草稿；默认只读。
- `danta_critic`：选题论证、设计、稿件和汇报的独立质疑与质量核查。

主引导负责倾听、拆解、恢复上下文、路由、合并与共享状态更新；简单任务由主引导直接完成。她不需要记 agent 名称。每项复杂交付由表中相应角色负责；角色配置存在不代表客户端已加载或本轮真实执行。

Skills 是各 agent 需要时读取的方法说明，不是 agent 本身。普通证据/方法/质疑专家不模仿真实教授，不与用户分别展开访谈，不递归派生其他 agent。使用当前环境允许的模型，不擅自换更昂贵模型。

## 何时使用

思路陪伴和初步选题由主引导负责，不把选题决定交给 agent。短编辑、单一数据库查询或简单组会整理通常只需一位负责人；有两个及以上独立问题时才并行。项目最多允许 3 个并发子 agent，不要求每轮全员参加。

例如：证据 agent 核查候选解释的已有研究，方法 agent 根据已确认资源评估可区分的验证路径，可以并行；如果方法选择依赖具体文献结论，应先等证据结果。论文 agent 只在证据和作者的关键决定明确后起草。质疑 agent 可独立审阅最终方案，再由主引导核对分歧。知识库 agent 给出归档草稿，主引导审阅并写入唯一权威记录。

## 调用与降级

先检查实际可调用的子 agent 工具和当前会话权限；如果支持自定义名称，选择对应角色。若只有通用 spawn 工具，在任务消息中完整提供该角色的边界和交接要求。仓库提供 `.codex/agents/*.toml` 项目配置；配置文件存在不等于客户端已经加载。

没有子 agent 工具时，由主引导依次做不同视角的分析，明确写“本轮为单 agent 分角色分析”；禁止伪造多个 agent 的完成记录或说独立复核已经发生。自动化、独立用户任务和额外外部服务不是本协议的默认组成部分。

## 派工内容

每次写清：任务ID、工作区、当前问题或状态版本、用户明确约束（如“先别定”）、具体问题、允许读取的文件/公开来源、已知事实、仍未确认的假设、交付范围、指定输出路径、停止条件。不向专家传递无关私人资料或整份聊天记录。

除写作、生信分析和科研表达 agent 在本轮授权的输出路径创建交付物外，专家默认只读。任何角色都不得修改原始数据、共享画像、决策日志和主状态；知识库 agent 仅提交待审阅草稿。交接统一使用下列结构：
1. 回显任务ID、所依据的问题/状态版本和用户约束；说明任务状态（完成/部分完成/无法完成）。
2. 稳定来源ID与真实链接/路径、阅读范围；区分本 agent 实际读取与用户/另一 agent 转述。仅收到“某摘要说”不能写成已读摘要。
3. 发现与推论，区分事实、假说及局限。
4. 与当前解释一致/不一致之处，以及如何进一步区分。
5. 尚缺信息和可执行的下一步。

联网工具不可用就写明未联网；主引导不能把部分完成当作已完成。超出边界的问题交还主引导，失败任务默认只针对明确原因调整一次，仍失败则保留缺口并继续可做部分，不无限循环。

## 汇总与记录

仅主引导写共享状态、画布、证据台账和决策记录，避免并发覆盖。核对来源和主张一致性；同一文献被多个 agent 引用仍只是一份证据；不同论文也可能使用相同队列、数据库或样本，未核实时标记独立性未知。多个 agent 赞同不代表独立重复验证，更不等于科学结论成立。

有分歧时展示分歧对应的事实、假设或方法差异，提出能化解分歧的最小核查；不按票数选方向。用简短自然语言把最值得本人思考的一点带回，不把三份专家报告原样堆给她。

只在实际派工后记协作记录：任务ID、角色、具体问题、实际运行方式、返回状态、来源索引、产物路径、主引导采纳/暂缓及理由。用户选择始终另记。

## 合并前与运行失败时

合并前先核对最新用户消息及当前画布：问题、约束或决定是否在任务运行期间改变。旧任务只可用于仍适用的部分，过时结论标明原适用范围，不覆盖新状态。需要复查时明确剩余问题，不自动重跑全套。

合并检查同一份交接中的任务ID、依据的状态版本、实际返回状态和来源ID；任一缺失只保留为待核查线索，不更新权威记录。测试/虚构来源及其派生摘要和导出始终保留测试标记，不参与真实画像或证据汇总。摘要、部分全文、全文已获取与全文已阅读分别记录；没有读到的章节不写成已核查。DOI/PMID 相同先按同一作品核对版本；不同作品共享队列或数据也不算独立重复，独立性未知时保持未知。缺样本量、数值或批准记录时留空并写明缺口；本地 `analysis_approval.json` 的存在或字段值不等于本人真实授权，执行分析前仍须核对本轮授权范围。工具超时、失败、空结果或仅有草稿时标“部分完成/无法完成”，不得记成任务完成或科学主张成立。

先确认派工工具返回了真实任务标识，再等待该任务；没有成功派工标识，不进入空等待循环。记录任务完成的依据是实际返回结果，不是“准备调用”的说明。网络中断、超时或空结果只影响相应子任务，主引导报告哪些内容尚未核查并继续可做部分；有明确可修复原因时至多调整一次，不无限等待或重试。

自定义角色不可用时，通用子 agent 必须实际获得对应角色的完整边界；标明“通用子 agent 按角色指令执行”。不能仅用文件名或角色名暗示已加载配置。

## 女娲蒸馏的专用流程

用户明确启动女娲时，执行 [expert-distillation.md](expert-distillation.md) 的六维职责、逐维落盘和独立验证规则；普通只读角色保持只读。允许写入的通用调研agent仅操作分配的顾问文件，不改共享研究档案。遵守实际并发上限，分批或串行不等于六个同时执行。顾问使用原模板的透明模拟视角，不表示真实教授参与。
