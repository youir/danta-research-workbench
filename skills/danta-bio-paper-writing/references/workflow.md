# 生物医学论文协作流程

## 阶段 1：接收材料并明确边界

确认本轮交付目标（开题文字、论文某章、投稿稿件、分析计划或图稿）、受众/格式要求、截止日期和可使用资料。若涉及新目录或批量读取，按工作台授权规则先取得龚博士本人对路径、文件类型、用途和摘要保存位置的明确授权。先列材料清单、拟阅读深度及未知；不要直接扫描全盘。

按实际状态建立“研究问题—数据/样本—方法—结果—解释—引文”映射。用“已完成 / 计划中 / 待核实”标记，优先复用知识库中经本人确认的记录。

## 阶段 2：确认分析环境与决定权

当任务涉及计算分析或复现分析时：

1. 检查 R、Rscript、RStudio 和项目锁定文件是否存在；仅报告检测结果，不自动安装软件包、打开数据或运行分析。
2. 提出清楚的后端建议及理由（如项目现有 R/RStudio 环境优先；不符合目标时解释原因），输出 `backend_decision.json` 草案供龚博士选择。
3. 只有收到对后端的明确选择后，才记录已选择；只有另获运行授权后，才读入指定数据并执行分析。`analysis_approval.json` 记录数据路径/范围、分析目的、输出位置、外部联网与隐私约束、获准动作和时间。授权不延伸到未提及目录、其他分析或外传。
4. R 不适用或不可用时说明限制。建议 Python 替代前解释差异并询问；不得悄悄换后端。
5. 每次运行记录脚本、环境/版本、命令、输入文件、输出及错误日志。失败即如实报告；不能依据预期生成“合理结果”。

分析环境输出约定见 [analysis-records.md](analysis-records.md)。

## 阶段 3：写作与证据核查

- 先给出与问题和实际材料相称的结构/章节提纲，并指出证据足够、证据冲突和缺失的位置。
- 方法应准确描述实际做过的流程；计划方案用将来式/计划标签。
- 结果仅陈述实际观测到的数据，解释放在讨论；按研究设计限制推论范围。
- 引用逐条核验作者、题名、年份、DOI/PMID、来源链接和所支持的主张。未核实的引用单独标注，不猜测补全。
- 生信分析按需记录队列来源与下载日期、样本纳排、样本层级划分、预处理、批次、代码/参数、软件包版本、统计检验、效应量和限制。
- 组学/机器学习须审查信息泄漏与患者/样本层级拆分；通路富集和数据库交集属于假说线索，不直接视为机制验证。

## 阶段 4：科研图稿

1. 先给图的论点、面板计划与每个箭头/关系的证据状态，请龚博士确认关键生物关系。
2. 制作要求触发 `danta-research-ppt`；优先交付可编辑 PPTX/SVG 和源文件，并保留上游许可与素材出处。图稿只表示证据允许的主张，不增添尚未验证的节点。
3. 病理影像使用获准、匿名化的真实图像；组学曲线/统计图由实际数据和脚本生成，不用示意图冒充分析结果。
4. 检查文字可读性、颜色/线型语义、图例、比例尺、单位、样本量、统计方法和图注独立性。留待作者核实的部分显式标记。
5. BioRender 等平台可以作为人工编辑选项；在工作台没有已验证的集成时只给图稿结构/素材清单，不声称已生成平台原生文件。

## 阶段 5：稿件输出与确认

以龚博士指定的稿件为唯一当前稿。需要从头启动论文工作流时，可记录 `manuscript_approval.json`，包含题目/目标、拟处理材料、格式、稿件真源、获准生成内容及待作者决定事项；未获明确批准前仅交付提纲或样稿。引文格式由作者/目标期刊决定；不默认 APA、Nature 或任意刊物要求。

她明确要求 LaTeX 时创建/更新 `mainbody.tex`；明确要求 Word 时生成可编辑 `manuscript.docx`。同时交付 DOCX/TeX 时标注哪一份为主稿及同步日期，避免无声分叉。保留图源和真实运行记录。每次交付附简短变更说明、待作者核实问题和下一步。
