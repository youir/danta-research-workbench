# 科研汇报与可编辑科研图

把图和演示稿当作研究思路的表达工具。思维优先，决策在人：龚博士决定研究主张、解释和最终取舍；AI 负责把问题、证据、关系、设计和未知整理清楚，制作可审查的草案。视觉上的确定感不能替代证据。

先阅读 [工作流](references/workflow.md)。制作 PPT 或科研图时使用固定上游 [PPT Master](https://github.com/hugohe3/ppt-master) v6.6.0；首次需要时，用随包安装器安装到当前私有工作区的 `.agents/skills/ppt-master/`。如果本技能本身位于该库的 `.agents/skills/`，直接调用安装器；如果主引导技能是全局安装，则依据当前打开的知识库路径显式传入 `--skills-dir <私有知识库>/.agents/skills`。不猜测 CWD 或全局安装位置。安装完成后先读上游 `SKILL.md` 并严格执行其规定的 `attribution_guard.py`、路由、加载次序和用户确认门槛。上游文件、完整性检查、署名/许可文件不得删改、跳过或绕过。

## 触发与产物

- 她提到要做 PPT、PowerPoint、汇报稿、组会或开题展示时，整理叙事和逐页结构，再制作可编辑 `.pptx`。
- 她要独立科研图时，按需要做一页图稿，并交付可继续编辑的 `.pptx` 以及图源 `.svg`；如果她指定期刊/基金格式或投稿格式，再按要求导出 PDF/PNG 并检查规格。
- 支持研究机制图、实验设计/技术路线图、样本流程图、研究框架/图形摘要、病理图版编排与基于真实数据的统计图。按图的实际用途选类型，不把所有科研图都画成机制图。
- 一段实质讨论或复盘结束时，先简短总结思路变化、已知与未知；如形成了值得向导师/组会展示的内容，可以问龚博士要不要进一步制成 PPT 或科研图。询问不等于自动制图；简单问答、尚未成形或她已拒绝时不提醒。
- 若只需要讨论提纲、机制关系清单或 Mermaid 草图，就先交轻量文字/矢量草稿；不要为小问题启动完整 PPT 工程。

## 科学图的证据审查

制作机制图前先整理节点—关系—来源表，并让龚博士有机会校正关键科学关系。每个节点和连线至少核对：实体/变量、关系类型与方向、物种/模型/细胞或组织背景、来源及页码/图表、证据状态与适用限制。来源没写清的机制、定位、因果方向或选择性，不由常识补齐；不确定的边删去或显式标为“推断”“待验证假说”“待核实”。关联证据不画成因果箭头。

机制图默认提供清楚图例：实线表示来源直接支持的关系，虚线表示推断或待检验关系；箭头、抑制线、相互作用线、转位/运输等符号只在相应含义获得材料支持时使用，并在图例解释。不同细胞区室、组织位置、模型或处理条件只有在资料支持时才标注。不要把几篇来自不同物种、细胞系、剂量或时间点的结果拼成一个已成立的通路。

实验设计/技术路线图逐项标明样本或模型、分组、干预与对照、时间点、重复单位、关键检测、主要终点和分析路径；哪些已完成、正在做、计划做、预期结果或备选方案要分层显示。未知信息留空或标“待龚博士确认”，不可补造样本量、随机化、盲法、排除标准或阳性结果。样本纳入/排除流图中的数量必须能回到登记表或分析记录。

病理切片、显微图、患者材料和其他真实观测图像必须来自龚博士提供或已授权访问的原文件。不得用生成式图像替代真实观察，不伪造细胞、染色、组织结构、比例尺或数据点，不覆盖原件；如需裁切、色彩调整或标注，保留原图、处理记录和可识别修改。图注根据真实信息记录样本/模型、染色或方法、比例尺、来源与处理。定量统计图须从实际数据和已说明的分析代码生成，标出单位、样本量、统计方法及不确定性；没有数据就只提供空白图框或绘图规格，不生成示例结果冒充结果。

## 绘制与交付

优先使用可编辑的 PowerPoint 文字、形状和连接线。PPT Master 可把受支持的 SVG 元素转成原生 DrawingML 对象，但复杂路径、位图和不支持的 SVG 效果仍可能不可编辑；交付时逐一说明，保留 SVG 等源图。不要把整页栅格化后称为“可编辑”。

默认仅使用当前对话提供或已授权的本地材料，导入时复制来源，不移动、不覆盖原文件。默认不联网搜图、不调用外部图像生成/重绘、云端检索或商业 API；也不得把未发表数据、病理图、患者信息或研究草案发送给外部服务。若工作所需的工具会将提示词、文件或图像发送出本机，先向龚博士说明服务、材料和用途，并取得明确授权；本机文件可读也不代表云端模型处理已获授权。

至少进行两类检查：

1. **科学内容**：节点与箭头逐项对照关系表；证据状态、模型语境、图例、图注和结果阶段准确；引用可回溯；计划不伪装成结果。
2. **文件与版面**：按上游要求进行结构/视觉 QA；画面无裁切、遮挡、错连或字迹过小；确认 `.pptx` 能打开，并抽查关键形状/文字/连接线是否可编辑；明确标出只能整体替换的复杂对象。

将 `.pptx`、`.svg`、提纲/科学关系表、简短来源清单及质检记录放入授权知识库：汇报稿放到 `08_成果输出_Outputs/04_科研汇报与答辩_Presentations/`，独立科研图放到 `08_成果输出_Outputs/03_图表_Figures/`，并更新对应 `00_index.md`。来源清单保留来源路径或文献 ID 和位置，不复制整份敏感材料。未完成上游 QA 时如实注明；生成草稿不等于龚博士或导师认可。

## 按需安装

需要真正生成 PPTX 或科研图且上游包尚未安装时，从本技能目录调用 `scripts/install_ppt_master.py`。安装器仅从固定官方 GitHub Release 下载 v6.6.0，校验整个压缩包 SHA-256 后安全解压到当前私有工作区的 `.agents/skills/ppt-master/`，不改写上游内容；安装包约 62 MB，首次使用需要网络。若本技能是全局安装，则传入由 Obsidian/项目路径确认的私有库 `.agents/skills` 完整路径。已有文件或不同版本时安装器不覆盖，停止并报告冲突。上游绘图工具要求 Python 3.10+；先检查版本，若 `python3` 过旧，优先使用 Codex 提供的 Python 运行时，再按当前任务需要配置依赖，不要用旧解释器硬跑。若没有新版运行时或下载受阻，仍可交付经标注的关系表或 Mermaid/SVG 草图；说明尚未生成/检查 PPTX，不绕过上游安装和完整性规则。

安装器只提供上游 skill 文件；不会自动安装其 `requirements.txt` 中所有可选依赖。先按本轮所选上游路线确认必需工具，只安装完成该任务所需的本地依赖，并说明渲染检查是否受限。特别注意上游依赖说明中 PyMuPDF 为 AGPL-3.0，只有明确需要 PDF 转换时再核对其许可；不默认安装。PPT Master 运行时的在线研究、搜图及图像生成能力在本工作台中默认关闭。
