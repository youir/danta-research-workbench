# Codex 直接 SVG 重建

用于制作科研示意图、流程图、机制图，以及把一张获准作为参考的图重建成可编辑矢量图。Codex 直接编写 SVG 文本，不经 Cell_ppt 的小描图像识别 API、ImageGen 或其他矢量化云服务。这样不消耗小描识别额度；Codex 本身仍使用其正常模型用量。

## 输入与隐私

- 从研究主张、经核对的节点—关系表、用户文字说明或已授权参考图中取得绘图内容。优先从结构化的科学内容直接画图，不为省额度而虚构或猜测数据、关系和图像细节。
- 如果需要让云端模型读取本地参考图、病理图、未发表结果或研究草案，先告知龚博士将通过 Codex 模型处理哪份材料、用途是什么，并取得针对这份材料的明确同意。已明确提供给当前 Codex 对话的文件，也遵循工作区授权规则。
- 病理切片、显微图和其他真实观测图像不能重绘成仿真的“真实图”；将原图作为独立图像对象保留，只制作经批准的标注、版式和图注。不能用 SVG 重建替代或伪造真实数据。
- 对普通科研概念图、流程图和机制图，可以根据证据表由 Codex 直接构建 SVG，不需要调用图像生成服务。

## 绘制步骤

1. 先完成工作流中的科学内容审查，固定各节点、关系、方向、条件、证据状态与图例。缺失项标成“待核实”或留白，不从图像外推未经支持的机制。
2. 用清晰的 SVG `viewBox` 规划画布；尽可能用 `<path>`、`<rect>`、`<circle>`、`<line>`、`<polygon>`、`<text>` 和 `<g>` 表达对象。文字保留为真实文本，连接线使用独立路径/形状，并用 SVG `marker` 定义箭头。避免把整张图嵌成一个 `<image>`。
3. 将 SVG 保存为工作流要求的源文件，保留可读的元素 ID、分组和必要注释；不用外链字体、外部图片、脚本或不受支持的滤镜。对真实观测图像只保留原图对象并记录来源。
4. 把 SVG 交给 PPT Master 的规定路由，依照已安装版本的支持范围把形状、文字和连接线转成 PowerPoint 对象。若复杂路径或 SVG 效果不能转成原生对象，保留 SVG 并在交付记录中说明哪些对象仍是整体图像。
5. 按工作流做科学内容和版面 QA：核对每个节点/连接与来源表，检查文字、裁切、遮挡、连线方向、图例、颜色和黑白可读性；打开 PPTX，抽查关键对象能否单独选择编辑。未核实内容明确标出，不报告未实际完成的检查。

## 路线选择

- 新图或依据文字/证据关系重建：直接构造 SVG，无需 API Key 或图像识别额度。
- 依据位图重建图中的示意性形状：仅在参考图的处理授权已明确时，以图像为视觉参考并由 Codex 写 SVG；不把参考图发送到小描或其他外部矢量化服务。
- 只需在 PPT 中展示原图：保留原位图作为单独对象，不必做矢量化。
