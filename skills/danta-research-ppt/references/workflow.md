# 科研图与汇报稿工作流

每轮只做当前需要的产物。龚博士已明确要交付文件时，少问已知信息；材料不足之处标待核实，先推进可做部分。研究判断和图中主张由龚博士审阅决定，制作工具不替代导师或领域专家判断。

## 1. 找准读者要理解或判断什么

只问尚未从当前对话和已授权记录中得到的关键问题：图/汇报用途、读者、需要对方做的判断、可用材料、输出格式和截止时间。组会后可直接从会议记录回看本次反馈；不要重复问卷。默认先做一个能供她校正的内容草稿，重要科学关系需确认时再停在相应确认点。

区分“需要汇报的研究事实”和“想解释的模型”。研究图可解释假说，但不能把假说视觉包装成结果。信息不全时先用标记明确的占位符或备选分支；不要用常见故事填空。

## 2. 清点来源与阅读范围

读取本轮明确提供或已经授权的资料。若要扩大文件扫描范围，先取得龚博士对目录、文件类型、用途和保存位置的同意。保留源文件位置、文献 ID、页码/图号；默认复制上游导入文件，不移动、不覆盖。

每个内容单元登记 `claim_id`、文字主张、来源、来源位置、研究背景/模型、证据状态、限制和是否需龚博士确认。状态至少区分：原文直接报告、本人已确认的实验/分析、由多条证据作出的推断、待验证假说、待核实、未来计划。引用摘要不冒充已读全文，相关性不冒充因果。

## 3. 为科研图选结构

在绘图之前，先选与问题匹配的图型：

| 图型 | 适用内容 | 重点核查 |
|---|---|---|
| 机制图 / graphical abstract | 分子、细胞、组织层级及关系 | 节点语境、每条连线的关系/方向/来源和证据状态 |
| 实验设计图 / 技术路线图 | 假说到模型、干预、对照、读数和分析 | 已完成与计划分开；组别、时间点、终点、样本量有据可查 |
| 样本流图 | 纳入、排除、失访或质控流程 | 数量和排除原因对应可追溯记录 |
| 病理图版 | 真实切片/显微照片、多染色或空间视野 | 原图来源、样本/染色、比例尺、裁切和标注记录 |
| 定量数据图 | 真实实验/临床/计算数据 | 数据集、单位、统计方法、N、重复单位和不确定性 |
| 汇报/组会 PPT | 围绕一项研究判断组织叙事 | 听众、时长、待讨论决定、逐页来源和结论边界 |

复杂图先做节点—关系草稿或一个简单关系表供龚博士审阅。机制图建议使用如下表头：

| 节点/关系 ID | 实体或变量 A | 关系与方向 | 实体或变量 B | 物种/模型/细胞/条件 | 状态 | 来源/位置 | 限制/待确认 |
|---|---|---|---|---|---|---|---|

只画可追溯、对这张图有解释作用的关系。文献间模型不同、关系冲突或方向不清时，分面显示、加语境标签或暂时留空，不合成单一通路。

## 4. 设计图例与证据状态

图例必须清楚说明线型、箭头头部、颜色和灰度各自表示什么。建议初稿采用：有明确来源直接支持的关系用实线；推断或待检验关系用虚线；相关性使用无方向连线或明确文字。促进箭头、抑制线、结合/相互作用、转位/运输等符号仅表示材料确实支持的语义，且在图例中解释。图例约定可按学院/期刊规范调整，但不能让符号改变证据强度。

节点状态可以用小标签区分“已观察/文献支持”“推断”“假说”“计划中”“待核实”；颜色不是唯一编码，以免黑白打印或色觉差异造成歧义。物种、样本、模型、细胞类型、组织区室、处理条件、剂量和时间点按来源标出，避免跨模型拼接。

## 5. 汇报提纲与生成

汇报稿先保留结构化 `outline.json`：每页/画面记标题、读者任务、核心主张、来源 ID 与位置、证据状态、图型/对象、计划状态和讲述备注。按使用时长及讨论目标定页数，不凑固定页数或结论。已完成、分析中、计划、预期和假说不得混在同一结果层级。

需要生成 PPTX 或可编辑图时，按随包固定安装器取得 PPT Master v6.6.0：`python3 "${SKILL_DIR}/scripts/install_ppt_master.py"`。如果当前技能来自全局目录，则在命令末尾传入当前私有知识库 `.agents/skills` 的绝对路径：`--skills-dir "<private-vault>/.agents/skills"`。只从 Codex 已打开的 Obsidian/项目路径取得这个目录，不猜 CWD。上游绘图工具需要 Python 3.10+；默认 Python 版本不足时，优先使用 Codex 管理的 Python 运行时。之后把其目录作为 `SKILL_DIR`，先读取上游 `SKILL.md`，逐项履行归属完整性检查、路径规则、唯一正确工作路由、文件加载顺序及其中明确要求的人类确认门槛。不得跳过它的 blocking gate；默认流程适合科研和组会汇报，不用 quick 路线绕过审阅。只要一张图时，生成一页独立画布即可，勿强行套整套论文汇报。

让 PowerPoint 文本、形状、线和连接符尽量保持原生可编辑；使用 SVG 时只使用上游已支持且经 QA 的 SVG 元素，并保留原始 SVG 源。真实显微图等像素证据作为单独图像对象保持不变，只在许可范围内添加图注/箭头标注。特殊滤镜、外部图片或复杂 SVG 可能无法转成可编辑形状，必须标注对象边界。

## 6. 专项图型检查

### 机制与概念图

- 检查每条线是否有依据，是否错误暗示方向、结合、激活、抑制、定位或因果。
- 每条边回链关系表中的来源与位置；源头未核实的边不画成实线。
- 图内标出关键模型、物种、细胞/组织背景或条件；不能用图示符号省略会改变结论的上下文。
- 通过版面图例分开直接证据、推断与假说；把关键未知留在图上，不隐藏异议证据。

### 实验设计与病理流程图

- 模型、分组、对照、干预、时间、样本量和终点逐项链接到方案或实际记录。
- 计划图注明“拟开展/方案草案”；完成图只写登记记录支持的事实。
- 病理/显微图保持样本身份安全；仅使用授权数据。标注样本或模型、染色/方法、比例尺和图像来源。必要时保留文件名或脱敏 ID，不把可识别患者信息写入公开资料。
- 任何裁切、旋转、色彩处理或伪彩映射都记在图像处理说明，不改变/删除不利观察。

### 定量结果图

- 从指定真实数据集和分析运行构建；如无数据则提供空白规格，不造一组可视化数字。
- 标注测量单位、分析单位、N/生物学重复、误差表达、统计检验和显著性定义。
- 复核图形尺度、变换、归一化、缺失值、排除及多重比较处理是否与方法一致。

## 7. 两道交付检查

### 科学检查

- 图/每一页回答既定问题；证据状态与计划/结果一致；叙事不超过材料支持范围。
- 图注、图例、模型、样本量、统计和来源足够让读者正确解读。
- 检查相反或不确定证据是否被图示隐藏；关键关系交给龚博士校正。
- 组会和导师意见仅按实际原话/记录归档，AI草案不写成导师结论。

### 文件和视觉检查

- 使用 PPT Master 规定的结构与视觉 QA；逐页/逐图检视裁切、遮挡、错连、过小文字、色盲安全和打印灰度可读性。
- `.pptx` 能打开且关键节点/文字/连接线可选择编辑；记录位图和不可编辑对象。
- `.svg` 使用结构良好、可复用的矢量结构；如再导出 PDF/PNG，确认分辨率、字体嵌入/替代及裁边符合本轮用途。
- 只声明确实运行过的 QA；系统检查不证明生物学结论正确。

## 8. 归档与反馈

组会、开题或阶段汇报放进 `08_成果输出_Outputs/04_科研汇报与答辩_Presentations/`；单独机制图、实验设计图、病理图版、定量图放进 `08_成果输出_Outputs/03_图表_Figures/`。保留需要重建的提纲/关系表、SVG 源、PPTX/PDF/PNG、简短来源清单和 QA 记录并更新索引。原始数据和敏感图像依旧留在机构获批存储处，知识库里只写合规引用路径或 ID。

修改稿保留版本和更改原因。导师或同伴提出的科学修正只有在龚博士确认后才更改“本人决定”记录；不同解释保留并列。公开投稿、发送材料、上传仓库等外部动作不由此技能自动执行。
