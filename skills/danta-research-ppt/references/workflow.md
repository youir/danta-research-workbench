# 从研究材料到汇报稿

## 1. 定义这次汇报要解决什么

组会不是把所有工作再讲一遍。先把“谁来听、希望听众带走什么、希望一起判断什么”说清楚。文献汇报、课题论证、进度汇报、困难求助、预答辩的叙事不同；把导师/评审真正需要判断的一两件事放在前面。

若上下文已有会议类型、时间或学校格式，直接复用。仅当缺失信息会实质改变材料选择或结构时，询问至多三个短问题。时间不明时不虚构演讲时长，先用合理草案并注明。

## 2. 提取材料而不是照抄材料

逐项提取与本次判断相关的信息，制作短的来源索引：

| 字段 | 记录方式 |
|---|---|
| 主张/事实 | 用自己的话概括，不改变量纲和比较对象 |
| 类型 | 文献证据、本人陈述、原始观察、分析结果、推断、假说或计划 |
| 状态 | 已完成、在进行、待启动、预期、未知 |
| 来源位置 | 文件/文献 ID、页码/图表/段落，或会议记录日期 |
| 限制 | 样本、方法、质量、适用范围或未核实项 |

同一结论由多份文件转述时回到最接近原始证据的来源。互相矛盾时并列说明，不替用户静默择一。无法读取的内容标成缺口，不用常识补齐。真实结果只由实际结果材料支持；开题预测和预期产出单独呈现。

## 3. 组织叙事与页序

优先采用适合问题的结构，而非僵硬模板：

1. 汇报标题与讨论目标。
2. 背景和临床/生物学观察，收束到具体问题。
3. 为什么现有证据尚未解决问题，哪些替代解释仍成立。
4. 研究设计、样本/数据及总体技术路线。
5. 分析模块或实验内容，各自对应哪个子问题、判别什么。
6. 已有结果/当前进度；没有结果时如实展示可用证据、正在做什么和阻塞点。
7. 讨论、局限、希望导师帮助判断的事项和下一步。

这是可选的故事线，不要求所有任务都使用所有章节。短组会可以合并；预答辩按学校格式；文献讨论围绕原文设计和证据。示范视频展示六个大块和约 15 页的个例，页数仅属那次演示，不作为本工作台默认规则。

## 4. 生成可编辑源文件和 PPTX

将每页标题、意图、正文层级、来源、图表处理与状态先写入 `outline.json`。在 `presentation-skill` 工作区按其版本命令生成 PPTX，保留提纲、证据清单和构建/校验记录，使后续更换一张新图或修订一个结论时无需从头生成整份稿。

原生对象的选择：

- 标题、说明、页码及流程标签：文本框。
- 步骤、机制或研究路线：可编辑形状与连线，内容复杂时拆成几页。
- 有数字和原始数据的结果：从有来源的数据生成图表；保留单位、样本量、误差与统计信息。
- 显微图、热图、UMAP 等：保留清晰的独立图文件和可编辑图注；能从数据重绘时同时保留来源表/脚本。不要声称嵌入的静态科学图本身可编辑数据。

默认尽量保持对象可选、可改、可替换；若某种复杂图只适合嵌入位图，明确说明它是图像对象，并保留源图和对应运行记录。不得把整页排成一张图片冒充可编辑 PPT。

## 5. 检查并将反馈写回

交付前逐页对照来源和提纲检查：

- 每个关键事实能否找到来源？来源是预印本、摘要还是全文？
- 结果、正在进行、计划与假说是否用不同措辞或标记清楚？
- 一页是否承担一个主要表达任务？对听众是否讲得清楚？
- 图表标题、图例、标记、单位、样本及统计说明是否完整？
- 文字、连线、图像和脚注是否易读且没有互相遮挡？
- `.pptx` 是否可在 PowerPoint/Keynote 等软件中编辑，图源是否可替换？

把审稿和会后反馈分为“龚博士决定、导师实际意见、AI建议、待核实事项”。只将人真实确认的变化更新到对应研究记录；PPT、提纲和会议记录互相链接，不复制成第二套研究台账。
