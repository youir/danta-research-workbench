## 第一轮：入口整理

1. 主导航收为“今天、研究任务、文献资料、汇报制图、设置”五个区域。原有研究记录、文献、日报、归档、PPT、组会和机制图仍保留，通过对应区域进入。
2. 首页只显示真正待接续的启动语、最近一张任务卡和自由问题输入。首页草稿会直接回填输入框；没有额外的空操作“恢复”按钮。全部任务卡放在“研究任务”。
3. 导出/导入任务备份移至设置。备份文件格式、合并规则和本机保存位置不变。
4. 各区域写明“新建任务”或“查看已授权资料”的区别，避免把只读资料入口误认为自动研究能力。

## 数据边界

## 本轮实现：接续与状态恢复

- **原对话接续：** 启动语优先交接到任务关联的 Codex 对话，另开对话放入次级入口；保留历史编号，避免覆盖后找不到旧对话。
- **交接现场：** 记录打开、复制与错误状态；失败后保留启动语和已知对话编号。异步返回只更新原启动语，防止切换任务后串入新任务。
- **磁盘自动保存：** 延续 Electron、本机 Node 桥接和现有任务卡结构，没有新增数据库或自动执行服务。正式桌面版启动前恢复状态，修改后合并写入，关闭前等待最后保存；旧版草稿首次迁移，磁盘状态优先于浏览器缓存。
- **历史恢复：** 最近版本独立保留，历史快照最多 10 份，半小时变化留档，每次进程首次保存变化时也留档。恢复前保留当前状态；状态文件损坏时寻找有效备份，找不到时报告错误并保留文件。恢复入口放在“设置 → 任务备份”。
- **数据边界：** 自动备份仅包含工作台状态，不包含 API Key、知识库路径授权或成果文件内容。Obsidian 授权仍由原有单独机制维护。

### 验证与限制

本机模拟验证覆盖磁盘重开、缓存迁移、主状态损坏、无有效备份、历史恢复与撤回、备份数量上限、并发保存、请求大小与来源限制、交接失败以及切换任务后的迟到响应。构建与既有任务卡测试通过；测试使用临时模拟数据，没有读取 GY 或创建真实 Codex 对话。

浏览器开发预览显示“浏览器预览”，只有正式桌面构建启用磁盘存储。此次为本机代码更新，尚未发布 Windows 安装包；Windows 原生关闭与更新安装仍需发行验收。正常关闭会等待保存，强制结束进程或断电仍可能丢失尚未落盘的最后修改。
