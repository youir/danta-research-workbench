# 工作台使用逻辑优化清单

检查范围：开始页、任务整理页、科研 PPT 模板与 Logo 选择、启动语弹窗、研究记录、文献与信息源、知识库状态。

目标流程：选工作 → 写清任务与材料 → 选呈现方式 → 检查启动语 → 进入目标 Codex 项目 → 继续或回看本次工作。

## 优化项

| 优先级 | 发现 | 处理 | 状态 |
|---|---|---|---|
| P0 | 网页任务整理区和 Codex 项目没有目标关联，启动语只能手动复制，无法确认新对话是否创建。 | 先验证 Codex 桌面端或受支持桥接是否允许按项目创建对话并预填启动语；成功后再做一键接续。 | 待技术验证 |
| P1 | 科研 PPT 页先展示大面积模板和 Logo 选项，科研主题、听众与材料输入在后，容易先挑外观再梳理科学内容。 | 调整为先整理汇报问题，再选择模板与单位标识，最后检查启动语。 | 已完成 |
| P1 | 科研 PPT 的内容输入没有明确提示，龚博士需要自行判断本次汇报应先准备哪些信息。 | 增加可跳过的汇报形式、目标、听众、时长选择，以及可编辑的内容填空框架；只提示填写真实材料和待讨论问题，不预设研究结论。 | 已完成 |
| P1 | 草稿和模板选择刷新后丢失，组会准备过程中断时容易重做。 | 草稿、选择项和文件名清单改为当前浏览器标签页暂存；刷新可恢复，关闭标签页清空。 | 已完成 |
| P1 | 研究记录和文献页面目前主要展示未连接状态，导航入口看起来像可直接查看数据。 | 研究记录与数据能力保持清楚的未连接状态；首页连接入口已指向知识库说明。 | 部分完成 |
| P2 | 首页“最近研究记录”没有真实记录数据，名称与实际状态不符。 | 改成“知识库连接状态”，并直接打开知识库说明。 | 已完成 |
| P2 | 任务页“独立工作区”“Codex 对话”“尚未同步”等文字容易让人以为网页已与 Codex 项目连接。 | 改为“网页任务整理区”和“手动接续”，直接说明网页暂未创建或同步 Codex 对话。 | 已完成 |
| P2 | 文件选择控件可能让人以为网页已读取并带上文件。 | 说明当前只记录文件名；要让 Codex 使用文件，仍需在对话中提供。 | 已完成 |
| P2 | 启动语弹窗没有讲清复制后的下一步；复制一次后按钮不可再用。 | 写明粘贴到目标 Codex 项目的新对话；允许再次复制。 | 已完成 |
| P2 | 弹窗关闭后键盘焦点未回到原触发位置。 | 关闭后恢复焦点，并为弹窗补充描述关联。 | 已完成 |
| P2 | 小屏顶部的说明和框架入口只显示图标，含义不明显。 | 增加悬停提示；再结合真实设备核对是否需要显示短标签。 | 部分完成 |
| P3 | 刷新期间恢复状态，但没有在应用中直接清空当前标签页草稿的入口。 | 增加清空当前暂存的操作，并说明会清除哪些字段。 | 待设计 |
| P3 | 研究记录、文献与知识库的入口分散，当前空状态之间的关系需要更多引导。 | 评估是否合并为“资料与连接”状态页，并保留知识库的单独入口。 | 待评估 |

## 本轮完成

- 首页状态入口从“最近研究记录”改为真实的“知识库连接状态”。
- 在任务页和机制图页标明这是网页任务整理区，避免与 Codex 项目混淆。
- 明确从网页手动接续 Codex 的步骤和当前连接状态。
- 草稿与选择项按标签页暂存；更新界面说明与前端 README。
- 在科研 PPT 内容区加入可选引导项和填空框架，明确研究事实只能来自汇报人提供的材料。
- 允许重复复制启动语，关闭弹窗后恢复键盘焦点。
