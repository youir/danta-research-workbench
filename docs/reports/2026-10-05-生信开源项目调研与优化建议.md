# 生信开源项目调研与优化建议

核对日期：2026-10-05（北京时间）。本轮查阅 GitHub 公共仓库、发布记录、README、许可证，以及本工作台相关实现；未安装候选、未运行其分析、未连接龚博士的私有知识库。本文是比较与实施建议，不表示功能已经接入。

## 结论

近期有值得吸收的更新。优先把当前“研究任务—步骤—成果预览”补成可核对的生信工作流：明确输入和运行条件，让成果关联真实运行记录，并使质控报告易读。继续使用现有 Codex 与 Obsidian；先复用分析工具和输出协议，再决定是否需要新的执行服务。

AIPOCH 已在 10 月 1 日的体验方案中讨论过，此次增量是其 10 月 4 日正式发布的 v0.35.0。BioDSH、ClawBio、CellTypePilot 等是相对于本工作台候选清单的新候选，不能称为今天才发布。仓库 push 时间只表示有推送，不等于核心功能有实质升级。

## 与当前实现的差距

1. 已有任务卡、研究步骤、草稿恢复、成果清单和预览，已有 Skill 路由中的生信输入/参数/质控记录原则。因此下一轮应连接这些能力，不再建立平行任务系统或另一个知识库。
2. `artifactPrompt.js` 的成果清单登记 id、版本、原件和预览；`artifactService.js` 校验清单和路径。尚未形成关联输入、脚本、参数、环境与真实执行结果的完整运行记录。现有 SHA-256 用于标识键，不能据此宣称成果内容不可变或可复现。
3. `ArtifactViewer.jsx` 对 HTML 清洗并禁用脚本、SVG 和交互。MultiQC 的 HTML 交互图不能假设直接可用。应先展示其结构化质控摘要和静态图；完整交互需另行设计隔离打开方式，不能直接放开普通 HTML 的脚本权限。
4. 任务接续与 Codex 对话交接已经存在，但工作台显示“交接成功”不能等同于分析正在运行或已经成功；真实状态必须来自具体运行记录。
5. 主引导已要求按任务安装依赖、保留原始数据和记录失败。前端尚可增加轻量的就绪信息，让她知道缺的是数据、环境还是结果，而无需理解技能名称。

## 推荐实施顺序

### 第一轮：生信材料与成果来源，低依赖

在“研究任务 → 当前步骤”内按需展开生信材料区；读取已有记录，最多追问会改变分析的缺项。显示：

- 本轮问题和希望获得的产物。
- 材料类型：公开数据编号、计数矩阵、单细胞对象、原始测序文件，或已有结果。
- 物种、参考版本、样本/分组与比较目标；已记录的不再重复填写。
- 当前可用能力：只可提供方案、可以检查材料、可以执行；由实际检测支撑。

执行仍沿用当前获授权 Codex 路径。每次真正运行使用唯一运行编号，关联步骤、实际输入、脚本、参数、环境、起止时间、退出结果、日志、输出及校验和。进程退出成功与结果检查通过分开显示；未记录则显示未知，不靠文本猜测。仅提出方案时不创建假的运行记录。

成果详情增加“来源与方法”折叠区，默认仍展示成果。重跑生成新的运行和成果版本，不覆盖旧文件。大输入文件的哈希按需计算/缓存；不为了展示状态读取整个未授权目录。

验收目标：龚博士能从一份图或报告找到其来源、实际方法和对应步骤；恢复任务后能看出哪些已执行、哪些只是计划。

### 第二轮：公开数据发现与质控汇总

优先复用官方 GEO 等 API 与 MultiQC 输出。公开数据发现返回物种、组织、研究设计、数据处理层级、编号和来源链接；下载前核对文件体积、可用磁盘和任务用途。存在编号不等于存在合适表达矩阵，更不等于样本信息完整。

已有质控报告先接入当前成果区：显示样本概况、异常项、来源报告和明确限制。对任意 HTML 维持现有隔离；针对可信报告如要完整交互，单独评估运行环境与资源加载，不能全局允许脚本。

验收目标：她能判断材料是否适合继续分析，并能查看真实质控依据；失败、不完整和未评估有明确区别。

### 第三轮：真实需求驱动的专项分析

如果实际使用的是单细胞，选择一个公开、小型且有预期结果的数据任务，比较现有 Scanpy 路线与一个候选模块；如果只有已有差异分析结果，先完善结果解读，不安装原始测序工具。空间分析、FASTQ 流程与远程服务器均按实际需求推进。

选择依据是完成同一真实任务的操作步骤、等待时间、重复确认次数、复现能力和维护负担。候选进入代码前锁定版本、检查具体许可和依赖，再进行隔离验证；当前没有声称这些验证已完成。

## 界面与投入取舍

主导航仍保持现有五区；生信材料放当前步骤，运行记录放步骤详情，质控与来源放成果预览，环境配置放设置。普通交流不触发填表，不增加强制审批或技能商店。技能选择、输入识别和状态校验由助理完成，用户看到具体任务与缺项。

高价值部分是龚博士的项目上下文、连续研究记录和与组会/论文的接续。通用 Notebook、工作流调度和质控计算已有成熟项目，优先调用或利用其产物。全套替换运行后端会带来配置迁移与维护成本，当前证据不足以支持。

本轮仅新增此分析记录，没有修改应用、科研 Skills、版本号，也未推送或发布。
