# 任务接续与阶段归档验证

日期：2026-09-30。验证对象：桌面版 v0.3.0 对应源码。Windows 安装包由 GitHub Actions 构建发布，安装运行需在使用者电脑上验证。

## 本次调整

- 各工作区通过统一任务数据结构和 `useResearchTasks` 维护草稿、阶段、状态、下一步、材料索引及关联对话；旧草稿复制迁移，原数据保留。
- “成果与来源”随输入保存，包含记录类型、名称、文件位置或链接、版本、来源定位与未决问题；接续启动语携带这些信息。
- 复用已有 Obsidian 归档写入接口，显式保存阶段快照后将相对路径和时间回写任务卡。同名保存创建新版本，不覆盖旧记录，不改变任务完成状态。
- PPT 进入机制图时创建关联子任务，复制前序内容和材料索引，返回继续原 PPT 任务；首页自由讨论使用独立模式。
- 整理与归档可在任何研究阶段进行，没有额外个人审核门槛。科研来源与未决问题照常留存。

## 验证范围

自动验证命令：在 `apps/danta-workbench-ui` 执行 `npm run build` 和 `npm run test:tasks`。

任务回归测试覆盖同类型任务独立保存、旧草稿迁移、未完成任务交接与归档、旧任务结构兼容、超长 Unicode 快照明确报错、机制图关联接续，以及授权写入和同名版本保留。

界面测试使用临时模拟 Obsidian 目录，只填入“功能验证（模拟）”与 `SOURCE-001` 等合成索引，没有读取或写入真实科研资料。完成以下操作：

1. 新建 PPT 任务，填写目标、下一步、等待补充状态与模拟成果索引。
2. 连接模拟库并开启归档范围，分别保存 v1、v2；确认两份 Markdown 都保留对应版本、来源与未决问题。
3. 刷新页面，从首页任务卡恢复 v2 和两份归档记录，任务状态仍为等待补充。
4. 进入机制图，确认前序内容与成果索引随关联任务带入；返回后恢复原 PPT 任务。
5. 生成启动语，确认包含任务编号、版本、来源、下一步和最新快照路径。
6. 检查窄窗口与桌面宽度下的表单布局；浏览器未记录错误。测试后关闭临时服务和页面，清理模拟库。

## 实际边界

成果索引由使用者登记，工作台引用路径而不读取或复制原文件。Codex 输出和历史对话不会自动回写任务卡。新对话仍需粘贴并提交；本轮没有新建真实 Codex 对话，也没有在 Windows 安装包中运行验证。

维护入口和数据流见 [科研工作流与能力路由](../architecture/科研工作流与能力路由.md) 与 [完整体系架构](../../08_完整体系架构.md)。
