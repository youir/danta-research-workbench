# Jev 接入科研工作台：当前路线

更新日期：2026-09-30。龚博士继续使用现有工作台、Obsidian 和文献流程；本阶段不要求安装 Zotero。Jev 只帮助处理公开来源的少量语义判断，不生成科学结论或自动改写知识库。

## 先复用什么

| 环节 | 现有能力 | Jev 补充的判断 | 保留的人工核查 |
|---|---|---|---|
| 科研日报 | RSS、公开文献来源和当前日报流程 | 候选较多时排定阅读顺序；标出题名或摘要中的主张疑点 | 去重、日期、来源真实性、全文及是否纳入日报 |
| 文献复盘 | Obsidian 文献证据与公开原文 | 在公开原文中定位相关段落，提示两段来源是否真的讨论同一问题 | 研究设计、病理指标、图表、上下文和证据强度 |
| 组会与论文写作 | 现有 PPT 与写作流程 | 检查一条拟引用的公开主张是否被给定公开片段支持 | 最终表述、未发表数据、机制解释和引用准确性 |

检索仍由 PubMed、Consensus、Semantic Scholar 等实际来源完成。社区 [`jev-mcp`](https://github.com/jkudish/jev-mcp) 提供 `jev_rerank`、`jev_find`、`jev_compare`、`jev_verify` 等工具；只有当前 Codex 客户端实际加载时才调用，失效时按原流程继续。Jev 的排序和概率都不是论文质量分。

## 配置与状态

桌面工作台的“设置”集中管理默认 Codex 工作区、Obsidian 知识库路径与授权、Jev API Key。Jev 密钥由桌面进程使用系统加密能力保存于本机应用数据，不写进 Git 或浏览器存储。保存时调用一次 [TypeSafe 官方 API](https://docs.typesafe.ai/api)，只提交固定示例句；**绿灯**表示上次真实验证成功，**红灯**表示未保存或最近一次验证失败。显示验证时间；网络和额度变化后可手动重新验证。

这盏灯证明工作台能验证 TypeSafe 密钥，不能证明 Codex 已加载 Jev MCP，也不能证明某篇论文的判断可靠。工作台的密钥不会自动复制给 Codex 工具。龚博士可在桌面设置中操作；[安装维护说明](../apps/danta-workbench-ui/桌面版安装与维护说明.md)提供隐藏输入的 PowerShell 命令。

## 使用边界

1. 先做确定性核查：来源 ID、DOI、版本、日期、单位、明显重复。剩余语义歧义才调用 Jev。
2. 发给 Jev 的内容限公开题名、短摘要、公开片段和泛化问题；使用临时编号在本机对应真实来源。私有 Obsidian 笔记、未发表结果、患者资料、内部讨论和完整 PDF 默认不外发。
3. 一次小判断能解决时不启动批量链。候选不足 4 条时跳过批量重排；最多处理 20 条公开候选。失败、超时、字段无效时恢复原始顺序。
4. 输出区分“检索返回”“Jev 提示”“原文核查”。只有原文核查能进入证据台账作为具体科学表述的依据。
5. 任何自动淘汰阈值都应先用龚博士领域内的代表性样本评估错放和漏放；不套用其他学科或演示图中的阈值。

## 后续顺序

| 次序 | 交付 | 判定标准 |
|---|---|---|
| 1 | 桌面设置、密钥验证和红绿灯 | 密钥不回显、不入 Git；绿灯对应真实 API 成功；失败仍为红灯 |
| 2 | 现有 Skill 按场景路由 Jev | 仅在工具实可调用、内容可外发时触发；记录实际调用和回退 |
| 3 | 小样本评估日报排序、段落定位、公开主张核对 | 对照原始流程，记录节省的阅读时间及错误；不以演示数据宣称有效 |
| 4 | 若需工作台内直接操作，再设计最小的公开来源预览与显式提交入口 | 逐项展示将发往 TypeSafe 的内容；不自动传输 Obsidian 私有资料 |

Zotero 与 Jadense 可作为今后独立需求评估；当前路线不依赖它们，也不因截图示例创建单细胞文献目录。
