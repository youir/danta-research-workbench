# 候选课题卡

按需要建立候选，不规定数量。由 AI 整理真实讨论，未定项保留；不要要求用户先填满。

- 编号、暂定名称、日期：
- 想法来源（本人/导师/文献/AI）：
- 起始观察与来源：
- 一句话问题与研究类型：
- 为什么值得弄清：
- 最接近研究与差异（检索范围、日期）：
- 候选解释或研究目标：
- 其他解释（适用时）及如何区分：
- 所需资源、已确认情况、时间及主要风险：
- 可能削弱主张或改变路径的结果：
- 本人倾向、理由及与导师待讨论事项：

## 三个回看节点

它们检查思路是否被偷换；暂定内容允许继续推演。节点全部填写不等于研究已经成立。

| 节点 | 当前理解 | 本人已选择/仍暂定 | 决定原话或明确标注的概述、日期 | 未决项与变化理由 |
|---|---|---|---|---|
| 问题边界与回答目标 | | | | |
| 文献定位与候选解释 | | | | |
| 主张、证据路径与资源 | | | | |

## 主张—证据映射

| 主张ID与范围 | 候选解释/目标 | 已有证据ID及能支持到哪一步 | 尚缺证据 | 计划比较/对照/分析 | 不同可能结果的含义 | 限制或资源依赖 |
|---|---|---|---|---|---|---|

计划获取的证据不是已经存在的结果。不清楚如何检验时可以补证据、缩小主张、调整设计、保留分支或暂缓，不强制二选一。描述型/预测型研究不必虚构根本机制。

## 决定状态与可推进性

- 决定：PROVISIONAL（暂定）或 CONFIRMED（用户已选择的工作基线，不表示假说成立或导师批准）：
- 可推进性：可推进 / 部分受限 / BLOCKED（具体动作受阻）：
- 如受阻：阻塞哪一步、原因、解除条件、仍可继续的工作：
- 本轮可推进的最小问题：

用户选择某问题继续，或明确要求比较方案时，可以带已列明的缺口形成草稿，不要求先完成验证。

## 需要比较多个候选时

| 候选 | 本人在意的价值 | 证据基础与创新边界 | 可检验性与资源 | 关键未知 | 本人选择及理由 |
|---|---|---|---|---|---|

默认呈现权衡而不排名。用户要求建议时标为 AI 建议，不能直接填进“本人选择”。

状态与决定变化写入工作台 `我的开题/07_决策记录/决策日志.md`。
